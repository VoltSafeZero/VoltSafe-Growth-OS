Now that the mailbox classification/access-control emergency fix is complete, start the full VoltSafe CMS Role + Widget + API Exposure Audit.

This is a security task. Do not refactor unrelated UI. Do not redesign anything. Do not implement broad fixes yet unless you find an immediate critical data leak; if you do, stop and report it first.

Goal:
Create a complete, factual audit of what every role-defined user can currently see and access in VoltSafe CMS, including:
- sidebar modules
- direct routes
- pages
- dashboards
- command centers
- widgets
- widget settings
- role-specific widgets
- buttons/actions
- API endpoints
- database queries
- private/team/shared data boundaries

The purpose is to lock down VoltSafe CMS so sensitive information is never exposed to users who should not have access.

PHASE 4 — Audit backend API endpoints

Search all backend routes and API handlers.

For every endpoint, classify it as:
- public
- authenticated only
- role-restricted
- permission-restricted
- owner/team/org scoped
- unprotected but should be protected

Flag endpoints where:
- frontend hides a feature but the backend still allows the call
- endpoint only checks logged-in status
- endpoint does not check role/permission
- endpoint returns sensitive data too broadly
- endpoint mutates data without proper permission checks
- endpoint leaks data across users, teams, accounts, organizations, or mailboxes
- endpoint exposes Gmail/email/calendar/capital/revenue/security data without strict access control
- endpoint exposes private Currents channels/messages to non-members
- endpoint exposes admin/security/audit logs to non-admins

PHASE 5 — Audit database query scoping

For role-sensitive modules, inspect DB queries and services.

Flag queries that:
- return all users’ data
- return all CRM records without ownership/team/org scoping
- return all Gmail/email data without connected account ownership/access checks
- return all calendar data without ownership/access checks
- return private Currents channels/messages to unauthorized users
- return capital/fundraising/investor data too broadly
- return revenue/finance data too broadly
- return executive widgets to unauthorized users
- return security/audit logs too broadly
