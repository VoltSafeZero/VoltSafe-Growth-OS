SECTION 2B — PREFER EXCLUSION BY SOURCE OVER INCLUSION BY SIGNAL

The existing candidate predicates based on owner, communications, open tasks, edits, or stage may still be calculated for comparison. However, do not make an OR-of-positive-signals heuristic the default architecture without first checking whether imported records can be identified directly.

A behavioral predicate such as:

owner exists
OR communication exists
OR open task exists
OR meaningful edit exists
OR stage changed

tries to infer whether a record is “real” from side effects. That logic will drift and require re-auditing whenever another bulk import occurs or the imported data shape changes.

There is a visible “Import Marinas” action in the application. The system must classify future imports correctly at ingestion time rather than repeatedly guessing later.

First inspect the leads schema, import code, migrations, and import workflow for fields such as:

- source
- origin
- source_type
- import_batch_id
- imported_at
- import_source
- ingestion_source
- created_by_import
- external_dataset
- provider

Report:

1. Whether an import-source or batch field already exists.
2. The exact column name and type.
3. The values currently stored.
4. The exact value or values representing the marina-directory import.
5. Whether all existing imported marina rows are consistently tagged.
6. Whether organic, manual, converted, or promoted leads are distinguishable.

IF A SOURCE FIELD ALREADY EXISTS

Calculate and report predicate E:

NOT marina-import source

For example:

source IS DISTINCT FROM 'marina_import'

Use the actual schema and stored value, not this illustrative literal.

Report:

- eligible count under E;
- excluded imported count;
- overlap with predicates B, C, and D;
- records included by E but excluded by the behavioral predicates;
- records excluded by E but included by the behavioral predicates.

Also calculate the combined predicate:

NOT imported
OR (
    imported
    AND (
        owner exists
        OR communication exists
        OR open task exists
        OR another explicitly approved promotion signal exists
    )
)

Report its exact count and row-level differences from B, C, D, and E.

IF NO SOURCE FIELD EXISTS

Recommend adding a durable import-origin field as part of Phase 1, such as:

source TEXT NULL

or a controlled enum if the codebase already uses enums safely.

Required future behavior:

- Every new marina-directory import must set source = 'marina_import' or the approved equivalent.
- Every import run should also receive an import_batch_id where practical.
- Organic/manual leads must receive a separate explicit source value or remain distinguishable through a documented null/default policy.
- Promoting an imported lead into active work must not erase its origin. Promotion state should be represented separately from import provenance.

Prepare a one-time backfill plan for the existing imported population.

The backfill proposal must include:

- the evidence used to identify the approximately 55,000 imported rows;
- safeguards against tagging organic leads incorrectly;
- dry-run counts;
- ambiguous-row handling;
- rollback SQL;
- verification queries;
- estimated implementation scope.

Do not execute the backfill during this acceptance run unless explicitly authorized. Report the plan only.
