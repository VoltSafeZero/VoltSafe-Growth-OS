3. State drift considerations (architect-style review focus area).This is the specific class of bug to look for in self-review:

What happens if the Gmail call partially succeeds? (E.g., 5 messages requested, 3 succeed, 2 fail.) Does Gmail's response indicate which IDs succeeded? Does the local mirror update only the succeeded ones?
What happens if the request is retried by the client (e.g., user double-clicks "archive")? Idempotent on Gmail's side, but does the local update path handle the second call cleanly?
What happens if a push event arrives mid-mutation, also updating the same label_ids? Race condition between inline mirror and push-driven sync. Document or guard.
If email_messages.label_ids is stored as CSV/JSON text (per the schema), what's the parse-modify-rewrite pattern? Use the same approach as toggle-star.
