4. Copilot context builder

Create:

server/services/capital-copilot-context.ts

It should assemble safe, structured context from existing Capital systems.

Available context:
- round summary
- command center summary
- weighted pipeline
- valuation/dilution summary
- allocation/close plan
- investor scoring
- engagement analytics
- data room/material status
- portal activity
- linked investor emails, snippets only
- follow-up queue
- risk flags
- reports generated in Phase 2J
- Cortex Intel relevant to Capital, if available

Context must be scoped:
- if investor_id is provided, include that investor and relevant linked records only
- if round_id is provided, include that round and related investors/materials only
- do not include unrelated Capital data
- do not include raw email bodies unless existing safe email-context pattern already allows it
- prefer summaries/snippets over full private text
- include source labels so the model can explain where claims came from

5. Copilot prompt discipline

Create a strict system prompt for Capital Copilot.

It must instruct the model to:
- only use provided Capital context
- never invent investor status, commitments, valuation, documents, or email events
- state when data is missing
- separate facts from recommendations
- keep sensitive/internal notes out of board-safe outputs unless include_sensitive=true
- never auto-send messages
- draft emails only as drafts
- preserve numbers exactly
- cite/source internally from context labels where possible
- be concise and action-oriented
