Expand and clean up VoltSafe CMS user roles, admin privileges, and permissions model.

Context:
In Admin → Users & Roles, the current Role dropdown includes:
- Master Admin
- Admin
- Manager
- Engineer
- Sales
- Customer Success
- Analyst
- Advisor
- Read Only
- Brand & Creative Director

This is wrong for the long-term VoltSafe CMS permission model.

Required changes:

A) Separate “Admin Access” from “Role”
Admin and Master Admin should NOT be normal user roles.

They should become a separate admin/superuser permission field controlled only by authorized admins.

New structure should be:

1. Role
This describes the person’s company function:
- Executive
- Manager
- Sales
- Customer Success
- Software Engineer
- Hardware Engineer
- Finance & Accounting
- Marketing & Communications
- Brand & Creative Director
- Operations
- Analyst
- Advisor
- Read Only

2. Admin Access / System Access Level
This describes system power:
- None
- Admin
- Master Admin

Important:
- A user can be Executive with Admin Access = None.
- A user can be Executive with Admin Access = Admin.
- A user can be Executive with Admin Access = Master Admin.
- Admin/Master Admin should grant system-level permissions, not replace the user’s real business role.

H) Data model changes
Find current user schema fields. Current screenshot/profile suggests fields like:
- globalRole
- department
- jobTitle
- userType
- role

Refactor carefully.

Recommended model:
- role: business role, enum/string
- adminAccess: none | admin | master_admin
- department: existing department value
- jobTitle: free text
- userType: internal | external or existing values

If the existing backend currently uses globalRole for admin permissions:
- Keep globalRole for backward compatibility if needed.
- Add a migration/path so:
  - globalRole = master_admin becomes adminAccess = master_admin
  - globalRole = admin becomes adminAccess = admin
  - all others become adminAccess = none
- Do not keep Admin/Master Admin in the role dropdown.
- Permission checks should use adminAccess for admin/system powers.
- Business-feature checks should use role + department + explicit permissions.
