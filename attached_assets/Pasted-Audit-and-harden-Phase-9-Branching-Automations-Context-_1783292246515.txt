3. Trigger Audit

Verify trigger behavior:

reply_classification:

* meeting_request triggers stop_sequence + create_task
* interested triggers stop_sequence + create_task
* unsubscribe triggers stop_sequence + suppress_recipient
* negative triggers stop_sequence + add_note
* auto_reply/out_of_office do not create sales tasks

clicked_link:

* technical terms match only intended links
* ROI/pricing terms match only intended links
* unsafe/empty URLs do not fire rules
* click event still works if branching evaluation fails

no_open_after_step / no_click_after_step:

* if implemented, verify timing logic
* if not fully implemented, ensure it is clearly marked as unsupported/deferred

recipient_status:

* unsubscribed/suppressed recipients stop future automation
* bounced/do-not-email recipients do not branch into sends

account_heat_score:

* if implemented, verify score threshold behavior
* if not fully implemented, ensure it is deferred clearly

4. Action Audit

Verify action behavior:

stop_sequence:

* recipient automation_status becomes terminal/paused as intended
* future automation tick skips recipient
* branch_status and branch_reason are set
* current_step is not corrupted

pause_sequence:

* recipient is paused and tick skips recipient

move_to_step:

* refuses missing step
* refuses already-sent step
* refuses lower/invalid step if unsafe
* updates current_step / next_step_due_at consistently
* does not send immediately unless intended

skip_step:

* if implemented, verify next valid step selected safely
* if not implemented, mark deferred

create_task:

* creates only one task per rule/event
* task title/body are useful and not full private email bodies
* assignment follows existing task conventions
* no task created for unsubscribe/negative/out_of_office/auto_reply

suppress_recipient:

* sets suppression state
* writes campaign_suppression when appropriate
* creates audit/event trail
* does not allow future sends

send_specific_step:

* confirmed deferred/logged, not accidentally active
* cannot bypass compliance if later enabled

add_note:

* writes safe note/activity if implemented
* if not implemented, logged as deferred
