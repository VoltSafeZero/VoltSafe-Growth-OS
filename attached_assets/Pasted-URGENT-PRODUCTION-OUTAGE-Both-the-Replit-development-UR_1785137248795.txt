LIKELY ROOT CAUSES TO CHECK
==================================================

Investigate all of these:

1. `startupComplete`, `isReady`, `appReady`, or equivalent is never set to true.

2. The ready flag is only set inside a `.then()` that never executes.

3. An awaited migration hangs indefinitely.

4. A rejected startup promise exits early before setting readiness.

5. A `finally` block that should set readiness is missing.

6. The frontend static middleware is registered only after long-running startup work.

7. The `/` startup route is registered before the SPA/static catch-all and always intercepts the request.

8. A wildcard middleware such as:

   app.use((req, res, next) => {
     if (!startupComplete) {
       return res.status(200).json({ status: "starting" });
     }
     next();
   });

   blocks all frontend requests indefinitely.

9. The readiness state exists separately in multiple modules and the route checks a different instance than the startup code updates.

10. Production startup code and development startup code use different readiness variables.

11. The application uses a startup IIFE whose error is caught but readiness remains false.

12. Background services such as Gmail sync, Cortex indexing, help-center indexing, seeding, or migrations are incorrectly treated as required before the frontend may load.
