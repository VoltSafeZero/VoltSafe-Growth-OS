VoltSafe CMS — CEO Cockpit Phase 6: Action Loop, Follow-Up Queue, and Accountability Trail

Goal:
Turn CEO Cockpit insights into safe, reviewable actions:
- create/update tasks
- draft Currents update requests
- track follow-ups
- maintain an accountability trail
- never auto-send messages
- never expose private channel or DM bodies broadly
- preserve CEO/CFO/admin permission boundaries

Context:
Phase 4 built GET /api/today/ceo-cockpit with 7 sections.
Phase 5 built 1:1 notes, deterministic agendas, commitment extraction, task creation from reviewed commitments, and draft update text.

Now build Phase 6 as a careful extension, not a rewrite.

Core requirements:

1. Action Queue model
Create a lightweight action queue for CEO Cockpit follow-ups.

Preferred table:
ceo_action_queue
- id
- type: ask_for_update | create_task | follow_up | resolve_blocker | schedule_1on1 | review_commitment
- status: draft | queued | completed | dismissed | snoozed
- priority: low | medium | high | critical
- source_section: team_pulse | blockers | silence_watch | commitments | one_on_ones | ceo_attention | communication_hotspots
- source_type: task | user | opportunity | meeting_note | current_message | install_workflow
- source_id
- assigned_to_user_id nullable
- created_by_user_id
- title
- body
- suggested_message nullable
- due_at nullable
- snoozed_until nullable
- completed_at nullable
- dismissed_reason nullable
- metadata jsonb
- created_at / updated_at

If an existing generic actions/reminders table already exists, reuse it only if it cleanly supports the above. Do not force-fit and create a mess.

2. Backend service
Create server/services/ceo-action-loop.ts with deterministic helpers:

- generateCockpitActions(cockpitPayload, actorUser)
  Produces suggested actions from the existing CEO Cockpit sections.
  It must dedupe against existing open action queue items.

- listCeoActions(filters)
  Supports status, priority, type, assigned_to_user_id, source_section.

- createCeoAction(input)
- updateCeoAction(id, patch)
- completeCeoAction(id)
- dismissCeoAction(id, reason)
- snoozeCeoAction(id, snoozedUntil)

- buildUpdateRequestDraft(actionId)
  Returns draft text only. Never sends.

- createTaskFromAction(actionId)
  Creates a real task only after explicit user action.
  Preserve source metadata:
  source='ceo_action_queue'
  sourceMeta={ actionId, sourceSection, sourceType, sourceId }

3. API routes
Add requireAuth + requireAdmin routes:

GET    /api/today/ceo-actions
POST   /api/today/ceo-actions/generate
POST   /api/today/ceo-actions
PATCH  /api/today/ceo-actions/:id
POST   /api/today/ceo-actions/:id/complete
POST   /api/today/ceo-actions/:id/dismiss
POST   /api/today/ceo-actions/:id/snooze
POST   /api/today/ceo-actions/:id/update-draft
POST   /api/today/ceo-actions/:id/create-task

Rules:
- No route may auto-send Currents messages.
- No route may send email.
- No route may create a DM conversation unless there is already a safe existing pattern in the app for doing that, and even then it must only happen after explicit user action.
- Draft routes return copyable text and optional link only.
- All routes must validate ownership/permissions.

“Action Queue”

6. Accountability trail
Every queue item should preserve enough metadata to answer:
- why was this suggested?
- what source section created it?
- what object/person did it relate to?
- who completed/dismissed/snoozed it?
- when did it change?

Add simple audit events if an audit table exists. If not, keep a status_history array in metadata or create ceo_action_events:
- id
- action_id
- event_type
- actor_user_id
- note
- metadata jsonb
- created_at

7. Safety / privacy requirements
Tests must prove:
- non-admins cannot see or mutate CEO actions
- private Currents channels are not included
- DM bodies are not broadly exposed
- no sendEmail/sendMessage/auto-send happens in these routes
- update drafts are copy-only
- capital-sensitive actions remain gated by existing capital permissions
- actions are deduped
- dismissed actions are not regenerated immediately
- snoozed actions are hidden from open view until snoozed_until
