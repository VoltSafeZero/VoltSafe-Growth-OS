Proceed with VoltSafe CMS Currents Phase 14A only: Slash Commands / Composer Quick Actions.

Do not work on Accounts, Contacts, CRM list views, Guest Currents, external collaborators, workflow automation, DM unread badge work, private channels, channel search improvements, presence panels, message reactions, or unrelated task features.

Goal

Add lightweight slash commands to Currents composers so users can trigger common actions faster.

Currents now supports:

* channels
* threads
* DMs
* group DMs
* attachments
* reactions
* pins
* structured items
* AI summaries
* Create Task
* typing indicators
* presence
* channel participants

Phase 14A should add composer-side slash command suggestions and simple command execution without building a large command framework.

Scope

Add only slash commands for existing Currents capabilities.

Start with these commands:

1. /task — create a task from the current draft/message context
2. /decision — mark/send as Decision
3. /risk — mark/send as Risk
4. /requirement — mark/send as Requirement
5. /pin — pin the sent message if supported in that context
6. /summarize — trigger existing summary action for current channel/thread/record context if low-risk

Keep Phase 14A simple. Do not add custom command management or external integrations.

Product behavior

When a user types / at the start of a composer draft, show a small command menu.

Example:

/task Create task
/decision Mark as decision
/risk Mark as risk
/requirement Mark as requirement
/pin Send and pin
/summarize Summarize this conversation

Filtering:

* Typing /ta should narrow to /task.
* Escape closes the menu.
* Arrow keys navigate if low-risk.
* Enter selects highlighted command if menu is open.
* Mouse click selects a command.

After selecting a command:

* The slash command token is removed from the draft.
* The user can continue typing the message/body.
* The selected command appears as a small pill above the composer, e.g. Command: Create task.
* User can clear the selected command before sending.

Execution behavior

/task

Preferred Phase 14A behavior:

* After message sends, open existing Create Task dialog/drawer prefilled from the sent message.
* If easier, create task directly only if existing UX already supports it safely.
* Must preserve existing Create Task behavior and source metadata.

/decision, /risk, /requirement

Preferred behavior:

* Send the message normally.
* After send succeeds, call existing structured-item mark route on the sent message.
* If note support exists, do not force a note in Phase 14A.
* Toast: Marked as decision, etc.

/pin

Preferred behavior:

* Send the message normally.
* After send succeeds, call existing pin route.
* Only in active channels.
* Do not allow in archived channels.
* Toast: Message pinned.

/summarize

Preferred behavior:

* Trigger existing summary action for the current channel/thread/record.
* Does not need to send a message.
* If too risky, include in menu only where existing summary button already exists and reuse that exact handler.

1. Slash commands do not bypass existing route auth.
2. Slash commands do not bypass archived channel write blocks.
