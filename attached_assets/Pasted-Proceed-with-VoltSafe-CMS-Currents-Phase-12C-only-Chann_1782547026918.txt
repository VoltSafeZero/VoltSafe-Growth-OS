Product behavior

For each selected channel, show a small people/member control in the channel header.

Example:

* # general
* 8 people · 3 online

Clicking the control opens a popover or dialog showing channel participants.

For now, “channel participants” can mean:

1. Users who have posted in the channel, plus
2. Users who have a channel preference row for that channel, plus
3. Admin/internal active users if already easy and safe.

Preferred simple approach:

* Use users who have participated in the channel through messages and/or preferences.
* Do not imply formal channel membership if none exists yet.
* Label as People in this channel or Channel participants, not Members if channels are still public.

Backend route

Add an authenticated route if needed:

GET /api/current/channels/:slug/participants

Response:

{
  "channel": {
    "id": 1,
    "slug": "general",
    "name": "General",
    "isArchived": false
  },
  "participants": [
    {
      "id": 1,
      "name": "Trevor",
      "email": "trevor@voltsafe.com"
    }
  ]
}

Rules:

1. Requires authentication.
2. Channel slug must exist.
3. Works for active channels.
4. Archived channels can still show participants read-only.
5. Return active/internal users only.
6. Do not return suspended/deactivated users.
7. Do not leak passwords, permissions, private fields, or session data.
8. Sort participants:
    * online first if presence is joined frontend-side, or
    * alphabetical if backend-only.
9. Cap results, e.g. 100.
10. Avoid N+1 queries.
