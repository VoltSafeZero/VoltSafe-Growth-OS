Implement Commit 1 of 3 only: the mark-spam / trust derived-column fix.

Stop after this commit for .dev verification before any domain-block deletion or email_filters retirement.

Context confirmed by audit:
block / mark-spam and trust / not-spam currently update label_ids and rely on the next Gmail sync to repair derived columns like is_inbox, is_spam, and is_unread.

That creates the split-brain bug:

* Inbox list hides the message immediately because label_ids contains SPAM.
* Inbox badge still counts it because is_inbox may remain true.
* Spam view may not show it because is_spam may remain false.
* Derived columns only become correct after a later Gmail sync.

Goal:
When Spam/Inbox label state changes, update the matching derived columns immediately in the same local DB operation.

Scope:
Only fix:

* POST /api/inbox/threads/:threadId/mark-spam
* POST /api/inbox/threads/:threadId/not-spam
* Any shared mirror/update helper those routes already use.

Do not:

* Delete domain-block / Other-tab machinery.
* Touch email_filters.
* Change /api/blocked-senders exact-email insert behavior.
* Add schema or migrations.
* Use db:push.
* Touch Gmail sync/OAuth, smartCategory, CRM, signatures, tracking, CID, reply, forward, or unrelated inbox logic.

A. Fix mark-spam

When POST /api/inbox/threads/:threadId/mark-spam runs:

After the Gmail threads.modify({ addLabelIds: ["SPAM"], removeLabelIds: ["INBOX"] }) best-effort call, update the local DB for all messages in that thread so that:

* label_ids contains "SPAM"
* label_ids does not contain "INBOX"
* is_spam = true
* is_inbox = false

Do not force is_unread.

Important:
Leave each message’s is_unread unchanged. A thread can contain messages that were already read and messages that were unread. Bulk-setting read/unread from a thread-level spam action corrupts per-message read truth. Spam messages stop affecting the inbox badge because is_inbox=false; their unread state should remain truthful.

B. Fix trust / not-spam

When POST /api/inbox/threads/:threadId/not-spam runs:

After the Gmail threads.modify({ removeLabelIds: ["SPAM"], addLabelIds: ["INBOX"] }) best-effort call, update the local DB for all messages in that thread so that:

* label_ids does not contain "SPAM"
* label_ids contains "INBOX"
* is_spam = false
* is_inbox = true

Keep existing behavior:

* Delete exact sender from blocked_senders.
* Insert exact sender into spam_trusted_senders.

Do not blanket-set is_unread=true.

Unread-state rule:
Preserve truthful per-message read state. If the original unread state before spam is not recoverable, leave is_unread unchanged during trust. Do not mark an entire thread unread as a shortcut.
