Implementation Phase 1 — Add batched outcome-status route

Add a lightweight authenticated backend route.

Suggested route:
POST /api/calendar/outcome-status

Request body:
{
“events”: [
{
“id”: “…”,
“providerEventId”: “…”,
“start”: “…”,
“end”: “…”,
“title”: “…”,
“crmMatches”: […]
}
]
}

Response:
{
“statuses”: {
“[eventId]”: {
“hasOutcome”: true,
“activityId”: 123,
“outcome”: “completed”,
“createdAt”: “…”,
“linkedObjectType”: “account”,
“linkedObjectId”: 456,
“linkedObjectName”: “Oak Bay Marina”
}
}
}

Requirements:

* Authenticated current user.
* Own calendar events only.
* Do not support team overlay events.
* Query activities where type = calendar_meeting_outcome.
* Prefer matching by rawContent.__meta.calendarEventId or providerEventId.
* Fallback only if safe:
    * same linked CRM entity
    * same event title
    * same event date/start
* Do not overmatch unrelated meetings.
* Return only minimal status data.
* Do not return full notes/rawContent unless needed.

If rawContent is stored as text:

* Parse safely.
* Handle malformed rawContent without throwing.
* Ignore records that cannot be parsed.

No migration unless absolutely necessary.
