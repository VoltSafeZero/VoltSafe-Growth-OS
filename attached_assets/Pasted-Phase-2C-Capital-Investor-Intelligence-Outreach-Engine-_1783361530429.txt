Phase 2C — Capital Investor Intelligence + Outreach Engine

Phase 2A and 2B are complete.

Current state:
- Capital module has investors, contacts, rounds, commitments, pipeline, and activity logging.
- Capital access is restricted to CEO Trevor and CFO Scott Carlson.
- Capital permissions tests pass.
- Capital foundation tests pass.
- Startup performance work is also complete with parallel migration batches and updated tests.

Now implement Phase 2C.

Primary goal:
Turn the Capital module from a static funding CRM into an intelligent investor follow-up and outreach system.

This should help Trevor and Scott know:
- which investors matter most
- who needs follow-up
- what the next action should be
- what round/cheque size they relate to
- what email should be sent next
- which investors are warm, cold, strategic, or high-priority

Do not loosen Capital permissions. All new Capital features must remain restricted to Trevor and Scott Carlson only.

Tasks:

1. Investor intelligence fields
Audit the existing capital_investors schema.

If fields already exist, use them. If they do not exist, add safe migrations for useful investor intelligence fields such as:
- priority_score
- fit_score
- warmth_score
- strategic_value_score
- cheque_capacity_min
- cheque_capacity_max
- target_cheque_amount
- likely_lead_investor boolean
- can_follow_on boolean
- sector_fit
- geography_fit
- investor_thesis
- relationship_source
- relationship_strength
- last_contacted_at
- next_follow_up_at
- next_step
- do_not_contact boolean
- disqualification_reason

Only add fields that fit the current architecture. Keep it practical.

2. Investor scoring helper
Create a backend helper that calculates an investor priority score.

The score should consider:
- current stage
- investor type
- target cheque size
- committed amount
- last contacted date
- next follow-up date
- relationship strength
- strategic fit
- warmth
- whether they are marked do_not_contact
- whether they can write a meaningful cheque
- whether they are tied to an active round

Use a simple transparent scoring model, not black-box magic.

Example scoring categories:
- Hot
- Warm
- Nurture
- Low Priority
- Do Not Contact

3. Follow-up queue
Add a Capital follow-up queue API and frontend view.

Suggested route:
- /capital/follow-ups

The follow-up queue should show:
- overdue follow-ups
- follow-ups due today
- upcoming follow-ups
- investors with no next step
- investors with no activity in 14+ days
- high-priority investors needing action

Each row/card should show:
- investor name
- investor type
- stage
- priority
- warmth
- cheque target
- last activity
- next follow-up date
- next step
- primary contact
- quick action to open investor detail

4. Pipeline intelligence
Enhance the pipeline page with intelligence summaries.

At the top of the pipeline, show:
- total target capital in pipeline
- total committed
- weighted pipeline estimate
- number of hot investors
- number of overdue follow-ups
- number of investors with no next step
- likely lead investor candidates
- strategic investors count
- family office count
- VC count
- angel/HNW count
- government/non-dilutive count if applicable

- priority score

6. Activity-to-intelligence updates
When activity is logged, update useful investor intelligence fields where safe:
- last_contacted_at when email/call/meeting activity is logged
- warmth_score if positive engagement is recorded
- next_follow_up_at if a follow-up date is added
- next_step when stage changes or notes are added

Keep this simple and safe. Do not create brittle automation.

7. Email draft integration
Add a Capital investor email draft generator entry point.

From investor detail and follow-up queue, authorized users should be able to click:
- Draft Follow-Up Email
- Draft Intro Email
- Draft Meeting Request
- Draft Investor Update
- Draft Close-the-Loop Email

The draft generator should use:
- investor name
- investor type
- stage
- previous activity
- relationship source
- round context
- cheque target if relevant
- VoltSafe company context
- latest Capital notes/activity
- selected tone/purpose

Do not auto-send emails. Draft only.

It should return only Capital-safe context for the selected investor/contact and should remain permission-protected.

- investor summary
- primary contact
- stage
- relationship context
- recent activities
- relevant round
- commitment status
- next step
- suggested talking points

It must not expose Capital context to unauthorized users.
