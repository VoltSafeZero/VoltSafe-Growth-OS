Proceed with VoltSafe CMS Currents Phase 9B only: Archived Channel Read-Only Hardening.

Do not work on Accounts, Contacts, CRM list views, group DMs, Guest Currents, external collaborators, slash commands, workflow automation, notification preferences, typing indicators, channel search improvements, or unrelated task features.

Goal

Make archived channels truly read-only across all Currents write paths.

Phase 9A added channel create/edit/archive/unarchive and already hides the main composer for archived channels. This phase should audit and harden every remaining action that could mutate archived channel content.

Audit and fix only archived-channel write behavior.

Do not add new channel management features.

Desired archived-channel behavior

When a channel is archived:

Allowed

Users should be able to:

1. View existing messages.
2. View existing threads.
3. View existing attachments.
4. View existing reactions.
5. View existing pins.
6. View existing structured items.
7. Search archived messages if already supported.
8. Open archived messages through View in Currents links.
9. Open archived messages from task source links.
10. Run/read summaries if summary is read-only and does not mutate channel content.
11. Admin can unarchive channel.

Blocked

Users should not be able to:

1. Post new root messages.
2. Post thread replies.
3. Add/remove reactions.
4. Edit messages.
5. Delete messages.
6. Pin/unpin messages.
7. Upload new attachments.
8. Add/remove Decision/Risk/Requirement tags.
9. Create new tasks from archived-channel messages, unless intentionally allowed and clearly documented.
10. Trigger any write that changes archived-channel message state.

Backend requirements

For every write route that can target a channel message, verify archived channel state before mutation.

Thread replies

If replying to a root message in an archived channel:

* Return 403.
* Do not insert reply.

Reactions

If reacting to a message or thread reply in an archived channel:

* Return 403.
* Do not insert/delete reaction.

Edit/delete

If editing or deleting a message in an archived channel:

* Return 403.
* Do not mutate message.

Pins/unpins

Already partially fixed in 9A audit. Verify both:

* pin
* unpin

Both should return 403 in archived channels.

Attachments

If uploading attachment to a current_message whose message belongs to an archived channel:

* Return 403.
* Clean up uploaded temp files.
* Do not attach file.

Viewing/downloading existing attachments should still work.

Structured tags

If adding/removing Decision/Risk/Requirement on an archived channel message:

* Return 403.
* Do not mutate structured items.

Create Task

Audit behavior.

Preferred:

* Allow creating a task from an archived message only if it does not mutate the archived message/channel.
* If current implementation writes back source metadata only to task tables, it may be allowed.
* If it changes message state, block it.

Document the decision clearly.

AI summaries

Audit behavior.

Preferred:

* Allow summary generation if it only reads archived messages and writes summary to separate summary/cache table.
* If it mutates channel/message state in a way that violates read-only, block it.

Document the decision clearly.
