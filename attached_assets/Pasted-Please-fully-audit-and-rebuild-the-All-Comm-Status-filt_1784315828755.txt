Please fully audit and rebuild the All Comm Status filtering logic on:

Pipeline → Leads & Accounts

The current behaviour is incorrect and cannot be trusted.

CONFIRMED PROBLEMS

1. RECENTLY CONTACTED IS BROKEN

Selecting Recently Contacted returns zero leads.

This is incorrect because many Leads/Accounts have recently been contacted, including at least one contacted today whose recent communication is already visible and updated inside the Lead record.

The filter is therefore not using the same communication data shown in the Lead detail view, or it is querying it incorrectly.

2. NO RESPONSE AND WAITING FOR LEAD ARE DUPLICATES

“No Response” and “Waiting for Lead” represent substantially the same operational state.

They should be consolidated into one clear status:

Waiting for Lead

Waiting for Lead must include any Lead/Account where:

- VoltSafe has sent at least one communication; and
- the Lead/Account has never responded;

OR:

- the Lead/Account has responded previously; but
- VoltSafe’s most recent communication is newer than their most recent inbound communication.

In plain terms:

The last meaningful communication was sent by VoltSafe, so the ball is in the Lead’s court.

Remove “No Response” from the dropdown after its records and logic are safely merged into Waiting for Lead.

3. VOLTSAFE OWES REPLY IS BROKEN

Selecting VoltSafe Owes Reply returns zero leads.

This is incorrect because there are Leads/Accounts whose latest communication was an incoming response and VoltSafe has not replied afterward.

VoltSafe Owes Reply must include any Lead/Account where:

- the latest meaningful communication is inbound from the Lead/Account or one of its linked contacts; and
- there is no later outbound reply from VoltSafe.

In plain terms:

The Lead spoke last, so the ball is in VoltSafe’s court.

4. DORMANT IS INCORRECT

Dormant must include:

- Leads/Accounts whose most recent communication was 60 or more days ago; and
- Leads/Accounts that have never been contacted.

A never-contacted Lead is operationally dormant and must be included in Dormant.

5. EMPTY-STATE MESSAGE IS MISLEADING

When a communication filter returns zero records, the page currently says:

“No leads found. Click ‘Import Marinas’ to populate your pipeline.”

That is wrong when the database already contains thousands of leads and the selected filter simply returned no matches.

Replace this with a contextual message such as:

“No leads match the current filters.”

Include a Clear Filters action.

Only show the Import Marinas onboarding message when the user truly has zero Leads/Accounts in the database.

CORE DESIGN REQUIREMENT

Communication status must be derived from the actual unified communication timeline.

Do not rely on a manually stored status field that can become stale.

For each Lead/Account, derive communication facts from all associated records, including:

- emails
- sent emails
- received emails
- email threads
- calls
- logged phone calls
- SMS or text messages, if supported
- meetings
- manually logged communications
- notes explicitly classified as communication activity
- linked Contacts
- all contact email aliases
- all contact phone numbers
- account-level communications
- lead-level communications

Do not count internal-only VoltSafe activity as external communication.

Examples that must not change the status:

- internal notes
- task creation
- record edits
- assignment changes
- stage changes
- Cortex processing
- internal @mentions
- internal VoltSafe-to-VoltSafe emails

AUTHORITATIVE STATUS DEFINITIONS

A. ALL COMM STATUS

No communication-status restriction.

B. VOLTSAFE OWES REPLY

A Lead/Account qualifies when:

- lastInboundAt is not null; and
- lastOutboundAt is null OR lastInboundAt > lastOutboundAt.

Equivalent operational definition:

The latest external communication was inbound.

This must work across all associated contacts and all supported communication types.

C. WAITING FOR LEAD

A Lead/Account qualifies when:

- lastOutboundAt is not null; and
- lastInboundAt is null OR lastOutboundAt > lastInboundAt.

Equivalent operational definition:

The latest external communication was outbound from VoltSafe.

This includes:

- leads that have never responded; and
- leads that responded previously but have not responded to VoltSafe’s latest message.

Remove the duplicate No Response filter.

D. RECENTLY CONTACTED

A Lead/Account qualifies when:

- lastCommunicationAt is within the configured recent-contact window.

Use 30 days as the default recent-contact window unless an existing documented product rule specifies another value.

Recently Contacted includes both:

- inbound communication
- outbound communication

Do not define Recently Contacted as outbound-only.

Display the actual window in the tooltip or filter description:

“Communication within the last 30 days”

Ideally make the day threshold configurable later, but do not delay this fix.

E. DORMANT

A Lead/Account qualifies when:

- lastCommunicationAt is null; OR
- lastCommunicationAt is at least 60 days old.

This means never-contacted leads are included.

Use an exact date comparison rather than approximate month logic.

F. NEVER CONTACTED

This may remain as a separate filter for convenience, but it is a subset of Dormant.

A Lead/Account qualifies when:

- lastInboundAt is null; and
- lastOutboundAt is null; and
- no qualifying external communication exists.

If Never Contacted remains in the dropdown, clearly understand that:

Never Contacted ⊂ Dormant

STATUS FILTERS ARE OPERATIONAL VIEWS

Do not force every Lead/Account into only one permanent communication bucket.

Some filters intentionally overlap.

Examples:

- A Lead contacted yesterday by VoltSafe may appear under:
  - Recently Contacted
  - Waiting for Lead

- A Lead that emailed VoltSafe today may appear under:
  - Recently Contacted
  - VoltSafe Owes Reply

- A Lead never contacted may appear under:
  - Dormant
  - Never Contacted

The filter should evaluate the selected rule against communication facts.

Do not convert this into a single mutually exclusive enum unless there is also a separate “current action owner” field.

SAME-TIMESTAMP AND THREAD RULES

Handle edge cases consistently.

1. If inbound and outbound timestamps are exactly equal, use:
   - message/thread ordering
   - sequence ID
   - source event creation order

2. Automated inbound messages must not normally create VoltSafe Owes Reply, including:
   - delivery notices
   - out-of-office replies
   - bounce messages
   - spam
   - automated confirmations
   - unsubscribe notices

3. Automated outbound system messages must not normally create Waiting for Lead unless they are a genuine sales/customer communication.

4. Drafts do not count as outbound communication.

5. Scheduled but unsent emails do not count.

6. Failed or bounced outbound sends should not count as successful contact unless product requirements explicitly say otherwise.

7. Deleted communications should be handled according to the source-of-truth policy and should not leave stale rollups.

LINKED-CONTACT AGGREGATION

The communication status belongs to the Lead/Account, not only to one primary contact.

Aggregate communications across:

- the account’s primary contact
- every linked contact
- account-level email aliases
- contact aliases
- account phone numbers
- contact phone numbers
- legacy contact links
- opportunity-associated contacts
- pilot/project-associated contacts where they belong to the same account

Avoid double-counting the same email or event when it is linked through more than one relationship.
