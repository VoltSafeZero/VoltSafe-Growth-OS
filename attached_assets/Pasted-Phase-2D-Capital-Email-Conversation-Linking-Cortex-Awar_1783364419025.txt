- subject
- direction
- participants_json or participants text/jsonb

- link_type:

  - manual
  - approved_review
  - ai_draft_sent
  - campaign_sent
- match_confidence
- match_reason
- created_by
- created_at
- updated_at
- deleted_at nullable

Add unique constraints to prevent duplicates:
- unique active link by email_thread_id + capital_investor_id

Use soft delete if that matches project patterns.

If an existing generic entity-link table exists, reuse it only if it cleanly supports all requirements.

3. Exact email matching by Capital contact email

Use capital_contacts.email as the primary automatic matching key.

When an email is sent to or received from an address matching a Capital contact:
- link the email thread/message to that capital_contact
- link it to the parent capital_investor
- create/update capital_email_links
- create/update a Capital activity entry of type Email
- update investor last_touch_at / last_contacted_at where applicable
- ensure duplicate syncs do not create duplicate activity

This should work for:
- inbound emails
- outbound emails
- replies
- manually composed sent emails
- AI-generated investor drafts once sent
- forwarded threads where there is a matched investor contact

4. Conservative domain/company fallback
