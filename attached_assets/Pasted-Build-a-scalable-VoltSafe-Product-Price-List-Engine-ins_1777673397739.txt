SKU FORMAT
Use this structure:

VS-[IND]-[COMMERCIAL_TYPE]-[POWER_OR_SCOPE]-[MODEL]

Examples:
VS-MAR-SYS-30A-SLIP
VS-MAR-HW-30A-CONN
VS-MAR-HW-30A-CTRL
VS-MAR-SW-CORE
VS-GEN-SRV-ENG-HR
VS-GEN-SRV-INTEG-PROJ
VS-GEN-LIC-OEM
VS-GEN-LIC-ROYALTY

Where:
- IND = MAR, RV, RES, COM, IND, EV, GRID, GEN
- COMMERCIAL_TYPE = SYS, HW, SW, SRV, LIC, ACC
- POWER_OR_SCOPE = 30A, 50A, 125V, 240V, 480V, CORE, OEM, ENG, etc.
- MODEL = SLIP, CONN, CTRL, PRO, ROYALTY, etc.

PRICING MODELS
Support these pricing model types:

1. one_time
Used for hardware, system kits, project services.

2. recurring
Used for software subscriptions.
Fields:
- billing_interval: monthly, annual

3. usage
Used for royalties, kWh, transaction fees, API usage, etc.
Fields:
- usage_unit
- price_per_unit

4. tiered
Used for volume pricing.
Fields:
- tiers array:
  - min_quantity
  - max_quantity
  - unit_price

5. custom
Used for licensing, partner deals, custom engineering packages.

QUOTE ENGINE LOGIC
Add a simple quote-builder abstraction.

When adding a SYSTEM product:
- Allow quantity input based on unit type.
- If system product has included components, optionally show included components beneath it.
- Do not clutter customer quote with internal components by default.

When adding SOFTWARE:
- Show recurring charge clearly.
- Example: 120 slips × $15 USD/month.

When adding SERVICES:
- Allow hourly quantity or custom project amount.

When adding LICENSING:
- Allow:
  - minimum commitment
  - royalty rate
  - estimated annual units
  - custom notes
  - term length

For now, keep licensing flexible. Do not over-engineer legal terms.

QUOTE DISPLAY RULES
