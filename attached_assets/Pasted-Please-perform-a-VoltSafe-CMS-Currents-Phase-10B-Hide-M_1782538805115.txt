Please perform a VoltSafe CMS Currents Phase 10B Hide Muted From Badge audit and polish pass only.

Do not work on Accounts, Contacts, CRM list views, group DMs, Guest Currents, external collaborators, slash commands, workflow automation, typing indicators, channel search improvements, or unrelated task features.

Goal

Verify that the new user preference for hiding muted unread messages from the main Currents nav badge is secure, accurate, performant enough, and regression-free.

Phase 10B added:

* current_user_preferences
* hide_muted_from_badge
* GET /api/current/preferences
* PUT /api/current/preferences
* /api/current/unread-counts preference-aware behavior
* Currents sidebar toggle
* Nav badge behavior excluding muted channel/DM unread when enabled

Audit scope

Audit only:

1. Preference schema/migration
2. Preference routes
3. /api/current/unread-counts behavior
4. Currents sidebar toggle
5. Main nav badge behavior
6. Row-level muted unread behavior

Schema checks

Verify:

1. current_user_preferences exists.
2. user_id is unique.
3. hide_muted_from_badge defaults to false.
4. created_at and updated_at exist.
5. Migration is idempotent.
6. Existing users are unaffected.
7. Deleting a user cascades preference row if intended.
8. No conflict with current_channel_preferences or current_conversation_members.is_muted.

Backend route checks

GET /api/current/preferences

Verify:

1. Requires authentication.
2. Returns only current user’s preference.
3. Defaults cleanly when no row exists.
4. Does not expose other users’ settings.
5. Response shape is exactly:
    * hideMutedFromCurrentsBadge: boolean

PUT /api/current/preferences

Verify:

1. Requires authentication.
2. Only updates current user’s row.
3. Rejects non-boolean payload.
4. Upsert works.
5. Repeated updates work.
6. updated_at changes.
7. Does not expose other users’ settings.
8. SQL injection is not possible.

Unread-count behavior checks

For GET /api/current/unread-counts, verify:

1. Default behavior includes muted channel unread.
2. Default behavior includes muted DM unread.
3. When hideMutedFromCurrentsBadge = true, muted channel unread is excluded.
4. When hideMutedFromCurrentsBadge = true, muted DM unread is excluded.
5. Unmuted channel unread still counts.
6. Unmuted DM unread still counts.
7. Sender’s own messages are excluded.
8. Deleted messages are excluded.
9. Archived channel messages do not create new unread.
10. Response includes hideMutedFromCurrentsBadge.
11. Existing row-level /api/current/channels unread counts are unchanged.
12. Existing row-level /api/current/dms unread counts are unchanged.

Performance check

Audit the current implementation.

Known concern:

* When hideMutedFromCurrentsBadge = true, the code may do one extra SQL query per channel with unread messages.

Verify:

1. This is acceptable at current channel scale.
2. It does not create obvious N+1 problems for DMs.
3. Server logs do not show slow query warnings.
4. If a simple JOIN/batch improvement is low-risk, apply it.
5. If not, document the current scale assumption clearly.

Do not over-engineer.
