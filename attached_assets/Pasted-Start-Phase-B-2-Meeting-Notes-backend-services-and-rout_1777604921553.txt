4. Validation:
   - title max 200 chars
   - status transitions enforced:
     scheduled_prompted or adhoc → recording
     recording → processing
     processing → completed / failed later
     any state → cancelled only by explicit cancel route if added
   - source enum:
     calendar, mail, adhoc, upload
   - platform enum:
     zoom, teams, meet, phone, in_person, other
   - linked_object_type enum:
     account, contact, lead, opportunity, project, ticket
   - action item statuses:
     suggested, accepted, rejected, task_created
   - audio chunk endpoint:
     - require status = recording
     - max chunk 1MB
     - content-type must be audio/*
     - safe stub storage only for now

5. Permissions:

   - read allowed if created_by = session user OR admin/master_admin

   - add-to-timeline/link-record should check CRM/target object access if available

6. Behavior:

   - process route should be a placeholder that marks/keeps status safely; no AI yet
   - create-tasks can be stubbed if task schema/service needs more review, but must not create bad data
