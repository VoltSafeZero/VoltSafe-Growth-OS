Proceed with Current Phase 2B only: Thread Replies.

Goal:
Add Slack-style thread replies to Current so users can reply to a specific message without cluttering the main channel feed.

Do not add @mentions, CRM record Currents, Guest Currents, direct messages, attachments, search, AI summaries, slash commands, or notifications yet.

Phase 2B scope

Add only:

1. Reply to message
2. Thread panel/drawer
3. Thread reply count
4. Thread message posting/edit/delete/reactions if naturally reusable
5. Clean unread/polling behavior for open thread

Backend requirements

Use the existing current_messages.parent_message_id field if it already exists. If it does not exist, add it idempotently.

A top-level channel message has:

* parent_message_id = null

A thread reply has:

* parent_message_id = root_message_id
* same channel_id as the parent message

Add/complete routes:

* GET /api/current/messages/:id/thread
    * Returns the root message and its replies.
    * Replies should include author info, timestamp, body, edited/deleted state, and reactions if available.
    * Exclude hard-deleted data. Soft-deleted bodies should be redacted like main feed messages.
* POST /api/current/messages/:id/thread
    * Creates a reply under that root message.
    * Body required.
    * Reject empty/whitespace-only replies.
    * Should auto-mark read for the sender if consistent with existing channel read behavior.

Update channel message fetch response to include:

* replyCount
* optionally latestReplyAt
* optionally latestReplyAuthor

Important:

* Thread replies should not appear as standalone top-level messages in the main channel feed.
* Main channel feed should only show messages where parent_message_id IS NULL.
* Reactions/edit/delete should continue to work correctly for both top-level messages and thread replies if the existing routes can support that cleanly.

Frontend requirements

Add a clean thread experience inside /current.

Message row

Each top-level message should show:

* A subtle Reply action in the hover action bar.
* If replies exist, show a compact link below the message:
    * 1 reply
    * 3 replies
    * optionally “Latest reply …”

Clicking Reply or the reply count opens a thread panel.

Thread panel

Add a right-side drawer/panel:

* Opens from the right side of the Current page.
* Shows the root message at the top.
* Shows replies below.
* Has a compact reply composer at the bottom.
* Can be closed with X and Esc.
* Does not navigate away from /current.
* Does not break the channel feed layout.
* Looks excellent in dark mode.

Thread composer

* Enter sends.
* Shift+Enter creates newline.
* Empty replies rejected.
* Auto-grow textarea if consistent with the main composer.
* After send, reply appears quickly and thread scrolls to newest reply.

Polling/query behavior

* Open thread should poll every 5 seconds while visible.
* Channel feed should still poll every 5 seconds.
* Avoid flicker.
* Avoid scroll jumping.
* Invalidate:
    * thread query after reply/edit/delete/reaction
    * channel messages query after reply so reply count updates

UX requirements

Keep it premium and restrained:

* No clutter
* No nested comment chaos
* No huge borders
* No ugly admin-panel drawer
* Smooth hover states
* Thread panel should feel native to VoltSafe CMS
* Deleted replies should show subtle “Message deleted”
* Edited replies should show subtle “edited”
* Reactions should render in replies if the existing ReactionStrip is reusable

4. Existing reactions still work.
