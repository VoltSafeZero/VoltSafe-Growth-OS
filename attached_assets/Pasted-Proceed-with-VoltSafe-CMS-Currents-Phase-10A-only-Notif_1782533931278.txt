Goal

Add basic notification preferences for Currents so users can control noise from channels and direct messages.

Currents now supports channels, DMs, mentions, unread badges, archived channels, attachments, structured items, tasks, and AI summaries. Phase 10A should add simple per-user mute/preference controls.

Desired preference levels

For Phase 10A, use simple levels:

Channels

* all — notify for all channel messages
* mentions — notify only when user is mentioned
* muted — no notifications, but unread counts may still appear muted/dimmed

Default: mentions or existing behavior, whichever best matches current system.

Preferred default for channels:

* mentions

Direct Messages

* all — notify for all DM messages
* muted — no notifications, but unread count may still appear muted/dimmed

Default:

* all

Data model

If no suitable table exists, add:

current_channel_preferences

Fields:

* channel_id
* user_id
* notification_level
    * all
    * mentions
    * muted
* created_at
* updated_at

Unique:

* (channel_id, user_id)

For DMs, prefer reusing existing current_conversation_members.is_muted if already present.

If a notification level is cleaner for DMs, add it to members:

* notification_level
    * all
    * muted

Migration must be idempotent.

Backend routes

Add authenticated routes under /api/current.

Get channel preferences

GET /api/current/channel-preferences

Return current user’s channel preferences.

Each item:

{
  "channelId": 1,
  "notificationLevel": "mentions"
}

Set channel preference

PUT /api/current/channels/:id/preference

Body:

{
  "notificationLevel": "muted"
}

Rules:

1. Requires authentication.
2. Channel must exist.
3. User can set own preference only.
4. Valid levels only: all, mentions, muted.
5. Upsert preference row.
6. Return updated preference.

Set DM preference

PUT /api/current/dms/:id/preference

Body:

{
  "notificationLevel": "muted"
}

or:

{
  "isMuted": true
}

Rules:

1. Requires authentication.
2. User must be a member of the DM.
3. User can only update their own member row.
4. Valid levels only.
5. Return updated preference.

Notification behavior

Update notification creation so preferences are respected.

Channel messages

If user has channel preference:

* muted: no notification
* mentions: notify only if user was mentioned
* all: notify for all messages, excluding sender

If no preference row:

* Use default behavior.

Do not notify sender.

DM messages

If recipient muted the DM:

* no notification

If not muted:

* notify normally

Do not notify sender.

Unread behavior

Important: muting should affect notifications, not necessarily unread counts.

Recommended:

* Keep unread counts working.
* Muted channels/DMs may still show unread badge, but visually subdued.
* Or hide unread badge for muted conversations if easier, but document clearly.

Preferred:

* Show unread badge, but muted row is visually dimmed.
