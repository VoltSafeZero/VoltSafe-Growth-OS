We need to prepare and implement a SAFE staged rollout plan for multi-user Gmail support in our CMS/CRM.

IMPORTANT CONTEXT:
- Right now the system supports only ONE connected Gmail account (Trevor’s)
- This current setup must NOT break
- We are already adding owner_user_id and source_account_id to email records
- We are already adding domain-based custom folders
- Existing CRM email-to-account/contact/lead matching must continue working exactly as it does now

GOAL:
Allow additional users to connect their own Gmail accounts in the future, while keeping mailbox data isolated per user unless explicitly shared by permission.

GENERAL RULE:
We are NOT building a shared free-for-all inbox.
By default, each connected Gmail account is private to the connected user.
Later we may add shared inboxes, but not in v1.

========================================
PHASE A — FOUNDATIONAL RULES
========================================

Implement and enforce these system rules everywhere:

1. Every email must belong to:
- a workspace_id
- an owner_user_id
- a source_account_id

2. Every connected Gmail account must belong to:
- one workspace
- one user

3. Every mailbox/folder/routing query must filter by:
- workspace_id
- owner_user_id
unless explicitly handling a future shared mailbox

4. No user should ever see another user’s private emails unless there is an explicit permission model allowing it

5. Existing Trevor Gmail functionality must continue working without any manual data loss or migration mistakes

========================================
PHASE B — EMAIL ACCOUNT MODEL
========================================

Create or update table: email_accounts

Fields:
- id
- workspace_id
- user_id
- provider ('gmail')
- email_address
- display_name (nullable)
- auth_status ('active', 'expired', 'revoked', 'error')
- access_token (encrypted)
- refresh_token (encrypted)
- token_expiry
- scopes_json (nullable)
- sync_enabled (boolean default true)
- last_sync_at (nullable)
- last_history_id (nullable if using Gmail incremental sync)
- sync_error_message (nullable)
- created_at
- updated_at
- disconnected_at (nullable)

Constraints:
- one active gmail account per email address
- one email account belongs to one user only

Indexes:
- workspace_id
- user_id
- email_address
- auth_status

Behavior:
- Trevor’s current Gmail must become the first record in this table
- All current emails should be backfilled to Trevor’s account as source_account_id

========================================
PHASE C — USER MAILBOX ISOLATION
========================================

Update mailbox logic so that all mailbox screens, folder screens, and email queries only show emails where:

- emails.owner_user_id = current_user.id
AND
- emails.workspace_id = current_user.workspace_id

Do NOT rely only on frontend filtering.
This must be enforced in backend queries and API access.

Apply this rule to:
- Inbox
- Sent
- Drafts
- Scheduled
- Other
- Custom folders
- Search
- Email detail view
- Unread counts
- Sync status

========================================
PHASE D — GMAIL CONNECT FLOW
========================================

Implement a Gmail connect flow for each user.

Requirements:
1. A logged-in user can connect their own Gmail account
2. OAuth tokens must be stored encrypted
3. The connection creates an email_accounts record tied to that user
4. Initial sync only imports that user’s mailbox into that user’s email scope
5. Disconnecting Gmail must not delete historical emails by default
6. If reconnecting the same Gmail later, preserve linkage where possible

UI:
- Add “Connect Gmail” in user settings or inbox settings
- Show connected account email address
- Show status:
  - Connected
  - Syncing
  - Error
  - Reconnect required
- Add Disconnect button
- Add Resync button

========================================
PHASE E — PER-ACCOUNT SYNC PIPELINE
========================================

Refactor sync logic so sync runs per email account, not globally.

Create service:
syncEmailAccount(emailAccountId)

Behavior:
1. Load email account
2. Refresh token if needed
3. Pull Gmail messages for that account only
4. Store imported emails with:
   - workspace_id
   - owner_user_id = email_accounts.user_id
   - source_account_id = email_accounts.id
5. Run existing CRM matching logic
6. Run domain folder routing logic
7. Update sync metadata:
   - last_sync_at
   - last_history_id
   - auth_status / sync error state

Critical:
- One user’s sync job must never import emails into another user’s inbox
- Failures in one account must not break other accounts

Implement a mailbox authorization policy.

Create permissions structure that can later support:
