Backend/API usage checks

Phase 7D should have made zero backend changes.

Verify:

1. GET /api/current/structured still works.
2. /current Structured Panel fetches all types for the selected scope.
3. Record Structured Panel fetches all types for that record.
4. itemType is no longer sent when the frontend needs counts from the full dataset.
5. scope=channel is sent explicitly for channel scope.
6. scope=all is sent explicitly for all-Currents scope.
7. scope=record is sent for record panels.
8. limit=200 is safe and sufficient for now.
9. API errors are handled.
10. No excessive duplicate requests happen on every render.

Count correctness checks

For /current Structured Panel, verify:

1. All count equals total returned items.
2. Decisions count equals only itemType === "decision".
3. Risks count equals only itemType === "risk".
4. Requirements count equals only itemType === "requirement".
5. Counts are computed before applying the selected filter.
6. Switching filters does not change the counts incorrectly.
7. Empty result count is displayed cleanly.
8. Counts handle zero values cleanly.
9. Counts do not show stale values after switching channel.
10. Counts do not show stale values after switching current-channel/all scope.

For Record Structured Panel, verify:

1. Counts are scoped only to that record.
2. Counts do not include channel/global structured items.
3. Counts do not include other records.
4. Counts update after marking/unmarking a record message.
5. Counts remain correct after switching between Search / Summary / Structured.

Client-side filtering checks

Verify:

1. All filter displays all loaded items.
2. Decisions displays only decisions.
3. Risks displays only risks.
4. Requirements displays only requirements.
5. Empty states use the filtered list, not raw data list.
6. The item cards rendered match the selected filter.
7. No hidden items are still counted incorrectly.
8. No double filtering happens.

Limit / pagination safety check

Because Phase 7D raised limit to 200 and computes counts client-side, audit this carefully.

Verify:

1. If total structured items are fewer than 200, counts are exact.
2. If total structured items could exceed 200 later, document that counts are “loaded count” rather than true total.
3. If the backend supports total counts, do not implement unless trivial.
4. If true counts need backend support, recommend it as a future scale improvement, not Phase 7D.

Do not add pagination or backend totals in this audit unless there is a serious bug.
