Now implement Navigation Consolidation Phase 2.

Primary goal:
Polish the consolidated navigation experience so users can quickly find tools without feeling buried. Grouped landing pages should feel useful, breadcrumbs should clarify location, and users should have fast access to favorites and recently visited pages.

This is a UX/navigation hardening phase.
Do not delete functionality.
Do not break old URLs.
Do not loosen permissions.
Do not expose restricted pages through search, breadcrumbs, favorites, or recents.

2. Grouped landing page polish

Improve grouped landing pages so they are not just link dumps.

Grouped pages should include:
- clear title
- short plain-English description
- cards or tabs for each underlying tool
- route link to each original page
- short “what this is for” text per card
- optional badge/count only if real data exists
- no fake stats
- no dead buttons
- loading/error/empty states where data is fetched
- permission-safe rendering

3. Breadcrumbs

Add or improve breadcrumbs across the CMS.

Breadcrumbs should show:
- parent category
- grouped section
- current page

Examples:
- Work / Inbox & Mail / Inbox
- Work / Calendar & Meetings / Meeting Notes
- Pipeline / Leads & Accounts / Accounts
- Operations / Knowledge & Documents / Document Hub
- Insights / Cortex / Cortex Intel Library
- Marketing / Engagement / Hot Accounts
- Capital / Investors / Investor Contacts
- Admin / Users & Roles / Role Manager

Requirements:
- breadcrumbs must respect permissions
- restricted pages should not leak through breadcrumb labels to unauthorized users
- old routes should show the new grouping where practical
- grouped landing pages should show two-level breadcrumbs
- active/current item should be clear
- breadcrumbs should not be visually noisy

4. Favorites

Add a lightweight favorites system for pages.

Users should be able to:
- favorite/unfavorite a page
- see favorite pages in Today or sidebar section if existing pattern supports it
- access favorites through command search
- persist favorites per user

Implementation options:
- Prefer existing user preferences API/storage if available.
- If no backend preference system exists, use localStorage as Phase 2 fallback.
- If using localStorage, keep the implementation simple and document it as client-local.

Favorite record should include:
- label
- route
- category
- icon if available
- created_at if available

Security:
- do not allow favoriting restricted pages unless the user currently has access
- if user later loses access, hide that favorite
- Capital favorites must remain hidden from non-Capital users

5. Recent pages

Add a lightweight recent pages system.

Track recently visited CMS pages:
- label
- route
- category
- last_visited_at

Show recent pages in:
- Today page if practical
- command search if practical
- optional sidebar mini-section if existing design supports it

Rules:
- cap recent pages, e.g. 8–12 items
- do not track public investor portal pages
- do not show restricted pages if user loses permission
- do not show Capital recents to non-Capital users
- avoid storing sensitive query params where possible

Command search should find:
- old page names

- recent pages

Requirements:
- command search must respect permissions
