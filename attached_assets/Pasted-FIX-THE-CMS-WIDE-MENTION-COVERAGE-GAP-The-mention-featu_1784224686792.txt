FIX THE CMS-WIDE @MENTION COVERAGE GAP

The @mention feature is currently inconsistent.

The screenshots show that typing “@scott” works in some areas but does not trigger autocomplete or create a linked mention in other text fields, including:

1. Task description fields
2. Task comment fields
3. Other plain textarea-based inputs

This is not acceptable.

The required behaviour is:

ANY user-editable text field anywhere in VoltSafe CMS that can save user-entered text must support the shared @mention system unless there is a specific documented security or technical reason it should not.

Typing “@” must trigger the same shared user autocomplete everywhere.

Selecting Scott Carlson must create a structured user-linked mention, notification, deep link, status record, and audit event using the global mention system already specified.

Do not patch only the fields shown in the screenshots.

This must be fixed at the shared component and architecture level.

CURRENT FAILURE TO INVESTIGATE

The likely issue is that mention support was added only to specific rich-text editors or specific module forms, while many other fields still use raw:

- textarea
- input
- Textarea component
- autosizing textarea
- plain contenteditable
- modal description editor
- comment composer
- notes editor
- inline edit field

Audit the actual code and confirm the root cause before changing it.

Do not assume every editable field uses the same component.

REQUIRED SOLUTION

Create one shared mention-capable text input system that can be used by every text surface in the CMS.

At minimum, provide shared components such as:

- MentionTextarea
- MentionInput
- MentionRichTextEditor
- MentionCommentComposer
- MentionContentEditable

Or one shared abstraction capable of supporting the existing editor types.

The shared component must handle:

- Detecting “@”
- Opening user autocomplete
- Searching active users
- Keyboard navigation
- Mouse selection
- Mobile selection
- Inserting structured mention metadata
- Rendering linked mention chips
- Extracting mention user IDs on save
- Passing mentions to the global mention backend service
- Editing existing structured mentions
- Removing mentions
- Restoring mention state when reopening an editor
- Preventing duplicate mention notifications
- Permission and sharing checks
- Deep-link source registration
- Mention status tracking

Do not duplicate mention parsing logic inside individual modules.

EXCEPTIONS

Do not automatically add mentions to fields where “@” is expected to be literal data rather than collaboration.

Examples that may be excluded:

- Email address fields
- Username fields
- Password fields
- API key fields
- URLs
- Machine-readable configuration
- Search bars
- Command palette
- Numeric fields
- Address fields
- External customer-facing form fields unless explicitly intended

Every excluded field must be documented in the coverage matrix with the reason.

Do not use broad exclusions based only on component type.

A textarea is not automatically exempt.

PLAIN TEXTAREA SUPPORT

Many existing fields may need to remain visually plain textareas.

That is fine.

They still need mention support.

Implement mention-aware textarea behaviour that tracks:

- Current cursor position
- Active mention query
- Text offsets
- Selected user
- Mention token metadata
- Text edits before and after the mention
- Deletion of the mention
- Copy and paste behaviour
- Multiline behaviour
- Scroll position
- Dropdown positioning

The autocomplete dropdown must appear near the active cursor where technically possible.

If exact cursor positioning is not practical in a legacy textarea, anchor it cleanly below or above the field.

Do not use that limitation as a reason to omit mentions.

STRUCTURED STORAGE

Do not rely only on storing visible text.

Each mention-capable record must save:

- Display text
- Structured mention metadata
- Mentioned user ID
- Mention offsets or token positions
- Source entity type
- Source entity ID
- Parent record
- Module
- Exact deep-link data

Where an existing database field stores plain text, add an adjacent structured metadata field if changing the primary field would create migration risk.

Example:

description_text
description_mentions_json

or:

content
content_json

Use the safest migration pattern based on the existing schema.

BACKWARD COMPATIBILITY

Existing plain-text values must continue to display correctly.

Old text containing “@Scott” must not automatically notify Scott.

Only structured mentions selected through the autocomplete should create active mention records.

Historical plain text may be upgraded only when the user edits the field and explicitly selects a valid person from autocomplete.

SHARED SAVE PIPELINE

Every mention-capable editor must submit through one shared save pipeline.

The save pipeline must:

1. Save the text content.
2. Save structured mention metadata.
3. Compare old mentions to new mentions.
4. Create newly added mention records.
5. Avoid re-notifying unchanged mentions.
6. Cancel or archive removed mentions.
7. Trigger permission checks.
8. Trigger access-sharing confirmation where needed.
9. Create notifications.
10. Create deep links.
11. Record audit history.
12. Return updated mention statuses.

Do not let individual modules directly create notifications independently.

USER SEARCH

The shared autocomplete must search:

- First name
- Last name
- Full name
- Display name
- Username
- Email
- Job title
- Business role

Typing lowercase “@scott” must still find Scott Carlson.

Search must be case-insensitive.

Rank exact first-name and username matches first.

PERMISSIONS

Mention support must not bypass record permissions.

If Scott lacks access to the record:

- Show the correct share confirmation.
- Do not silently notify him.
- Do not expose restricted preview text.
- Grant only the minimum permitted access after confirmation.
- Block the action if the author cannot share.

This must work consistently in textarea-based fields too.

DEEP LINKS

Every editor must register enough context to create an exact source link.

For example:

- Module
- Record ID
- Tab
- Section
- Comment ID
- Description anchor
- Timeline item ID
- Modal or drawer state where needed

Opening the mention must scroll to and highlight the exact field or comment.

COMPONENT ENFORCEMENT

Prevent future fields from silently missing mention support.

Add one or more safeguards:

1. Create a standard CMS text-field wrapper and require collaborative text fields to use it.
2. Add an ESLint rule, code audit test, or static scan that flags raw textarea usage in collaboration modules.
3. Add a developer checklist for mention-capable fields.
4. Add automated coverage tests for registered mention surfaces.

The rule should not flag valid excluded fields such as email inputs or search boxes.
