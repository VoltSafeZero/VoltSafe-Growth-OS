VoltSafe CMS — Today Page: Executive Operating Cockpit

Current completed state:

Major CMS systems are now strong:
- Capital Phase 2A–2L complete and release-ready
- Marketing drilldowns complete, including export/actions/polish
- Pipeline, Insights, Operations, and Work drilldowns complete
- Navigation consolidation complete
- Favorites and recent pages added
- CURRENTS attachments, Files tab, and search/history polish complete
- Build currently passes after fixing UniversalDrilldownSheet and current.tsx syntax issues

Now build the Today Page into the default executive operating cockpit.

Primary goal:
When a user opens VoltSafe CMS, the Today page should immediately show the most important work, risks, messages, meetings, follow-ups, blockers, and opportunities for that user.

For Trevor/CEO, Today should answer:
- What needs my attention today?
- What is overdue?
- What is blocked?
- What meetings are coming up?
- What important emails/messages need response?
- What hot accounts or deals need follow-up?
- What marketing/compliance risks need attention?
- What operations/support/procurement issues are blocking progress?
- What Capital/funding items need action? Only for Trevor/Scott.

For regular users, Today should be scoped to their work and permissions.

Do not modify unrelated modules.
Do not weaken permissions.
Do not expose Capital to non-Capital users.
Do not fake data.
Do not call Gmail/Calendar/external APIs directly from Today unless there is already a local synced table/API pattern.
Use existing local DB-backed data and existing APIs wherever possible.

1. Audit current Today page

Before writing code, inspect:
- Today page route/component
- current dashboard/home page behavior
- App.tsx default route behavior
- sidebar/nav link for Today
- user permissions/auth context
- existing APIs for tasks, meetings, mail summaries, campaigns, marketing drilldowns, operations drilldowns, work drilldowns, capital follow-ups, CURRENTS mentions/messages
- existing card/KPI components
- existing UniversalDrilldownSheet
- existing grouped landing page components
- existing favorites/recent pages hooks

Document:
- what Today currently shows
- what data is already locally available
- what APIs can be reused

- what data should be permission-gated
- what should be out of scope

2. Build backend summary endpoint

Add a backend endpoint:

GET /api/today/summary

Requirements:
- require authentication
- return only data current user is allowed to see
- use local database-backed data only
- do not proxy external Gmail/Calendar APIs
- keep endpoint fast
- cap list sizes
- include generated_at
- include safe empty states

Suggested response shape:

{
  generated_at,
  user,
  sections: {
    priority_actions,
    schedule,
    tasks,
    inbox,
    currents,
    pipeline,
    marketing,
    operations,
    capital,
    favorites,
    recents
  }
}

Each section should include:
- title
- count
- items
- severity/priority where applicable
- link or drilldown config where applicable
- empty_state

3. Priority Actions section

Create a top section called “Priority Actions”.

This should aggregate the highest-value items from the rest of Today.

Examples:
- overdue tasks assigned to me
- meetings starting soon
- high-priority emails needing reply if locally available
- CURRENTS mentions or unread important messages if locally available
- hot accounts requiring follow-up
- blocked installs/deployments
- critical support tickets
- procurement blockers
- campaign compliance blockers
- Capital follow-ups, only if user has Capital access

Rules:
- max 8–10 items
- sort by urgency and severity
- each item should have a clear action label
- each item should link to source page or open drilldown
- no fake priority scoring
- if confidence is low, use explicit source reason instead of pretending AI certainty

4. Schedule section

Show today’s meetings/events if locally available.

Include:
- next meeting
- meetings today
- meetings this week count if useful
- meetings missing notes
- meetings needing follow-up

Actions:
- open calendar/meeting page
- open meeting notes if available
- create follow-up task if existing task creation pattern supports it

If local calendar data is not available:
- show useful empty state and link to Calendar & Meetings
- do not call external Google Calendar directly in this endpoint

5. Tasks section

6. Inbox / Mail section

Show only locally available mail data.

Possible metrics:

Actions:

Do not directly query Gmail API from Today.

13. Today page UI

Design the Today page as a clean operating cockpit.

Suggested layout:
- Header: “Today”
- Subheader: date, generated_at, maybe user name
- Top row: Priority Actions
- Next row: Schedule + Tasks
- Next row: Inbox + CURRENTS
- Next row: Pipeline + Marketing

UX requirements:

14. Drilldown integration

Today metric cards should open UniversalDrilldownSheet where supported.

Examples:
- overdue tasks → /api/work/drilldown?metric=tasks_overdue
- campaign blockers → /api/marketing/drilldown?metric=campaigns_blocked
- blocked installs → /api/operations/drilldown?metric=blocked_installs
- hot accounts → /api/insights/drilldown or /api/marketing/drilldown depending existing source
- quotes awaiting response → /api/pipeline/drilldown

Keep the pattern:
See number → click it → inspect records → act.

15. Permissions and privacy

Tests must prove:
- unauthenticated users cannot access /api/today/summary
- Today summary only returns user-authorized data
- Capital section excluded for non-Capital users
- Admin-only items excluded for non-admins
- private CURRENTS content excluded unless member
- no raw storage keys
- no raw portal tokens
- no private Capital data in generic priority actions for unauthorized users

16. Performance

Today must be fast.

Rules:
- cap each section list, e.g. 5–10 items
- no unbounded queries
- no giant joined payloads
- no external API calls
- use existing indexed fields where possible
- if a section is expensive, return a lightweight count/link and lazy-load later
- log slow Today endpoint in development if existing pattern supports it
