Goal:
Close the executive operating loop.

CEO Cockpit should not only detect signals. It should help Trevor:
- prepare for 1:1s
- capture notes during/after 1:1s
- extract commitments from notes
- create/track follow-up tasks
- draft update requests to team members in CURRENTS
- see whether commitments actually moved after the meeting

Important philosophy:
Build this as a coaching, unblock, and accountability system — not surveillance.
Do not track keystrokes.
Do not track mouse movement.
Do not shame team members.
Do not auto-send messages.
Do not expose private DMs/channels unless Trevor is a member.
Do not fabricate commitments.
Do not rely on AI-only inference without user review.

2. Add 1:1 notes data model if needed

If a dedicated 1:1 notes table does not exist, add one.

Suggested table:

one_on_one_notes
- id
- owner_user_id                 -- CEO/user creating the note
- team_member_user_id           -- person the 1:1 is with
- calendar_event_id nullable
- title
- meeting_date
- notes_text
- wins_text nullable
- blockers_text nullable
- priorities_text nullable
- support_needed_text nullable
- decisions_text nullable
- followups_text nullable
- private_to_owner boolean default true
- created_at
- updated_at
- deleted_at nullable

Important:
- Notes are private to the creator by default.
- Do not expose 1:1 notes broadly.
- Do not store notes in localStorage.
- Do not make notes visible to the team member unless explicitly designed later.

If an existing meeting-notes system is strong enough:
- reuse it
- add a type/category for one_on_one
- preserve existing behavior

3. Backend 1:1 notes APIs

Add safe APIs:

GET /api/today/ceo-cockpit/one-on-ones/:teamMemberId/notes
POST /api/today/ceo-cockpit/one-on-ones/:teamMemberId/notes
PATCH /api/today/ceo-cockpit/one-on-ones/notes/:noteId
DELETE /api/today/ceo-cockpit/one-on-ones/notes/:noteId

Requirements:
- requireAuth
- requireAdmin or same CEO/executive guard used by CEO Cockpit
- verify note owner
- no normal user access
- no broad team visibility
- validate teamMemberId
- sanitize/bound note length
- soft delete preferred
- return safe metadata only
- no Capital data mixed into 1:1 notes unless explicitly in note text by user

5. Commitment extraction from 1:1 notes

Add a reviewed extraction flow.

When a 1:1 note is saved, the user should be able to click:

“Extract commitments”

The system should identify candidate commitments from:
- action items section
- followups_text
- notes_text if safe
- deterministic patterns first:
  - “I will…”
  - “Follow up…”
  - “Need to…”
  - “By Friday…”
  - checkbox-style lines
  - owner/date phrases

Optional AI:
- If existing AI helper is safe, add AI-assisted extraction
- AI output must be review-only
- AI must not create tasks automatically
- AI must preserve exact wording where possible
- AI must not invent owners/dates
- deterministic fallback must work without AI/API keys

Add endpoint:

POST /api/today/ceo-cockpit/one-on-ones/notes/:noteId/extract-commitments

Response:
{
  candidates: [
    {
      title,
      owner_user_id,
      due_date nullable,
      source_quote,
      confidence,
      suggested_priority,
      needs_review: true
    }
  ],
  warnings
}

    {
      title,
      owner_user_id,
      due_date,
      priority,
      source_quote

}

Requirements:
- require CEO/executive guard
- user must review candidates first
- create tasks using existing task system
- source should be one_on_one_note
- source_id should reference noteId if task schema supports it
- link task to team_member_user_id where possible
- return created task IDs
- do not create duplicate tasks if same note/candidate already converted
- do not assign tasks to invalid users
- do not auto-create commitments from AI without review
