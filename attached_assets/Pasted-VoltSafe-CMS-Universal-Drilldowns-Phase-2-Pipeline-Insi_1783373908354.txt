VoltSafe CMS Universal Drilldowns — Phase 2: Pipeline + Insights

Current completed state:
Marketing module universal drilldowns are complete.
- Backend: GET /api/marketing/drilldown
- 31 metric types
- requireAuth + crm:view
- reusable MarketingDrilldownSheet component
- wired across Compliance Dashboard, Marketing Dashboard, Campaigns, Hot Accounts, Replies, Audiences
- tests/marketing-drilldown.test.cjs passing: 155/155

Now implement universal clickable drilldowns for Pipeline and Insights.

Primary goal:
Any number, summary card, risk badge, chart segment, table row, warning, score, forecast metric, or health indicator in Pipeline and Insights should be clickable and show the granular underlying records.

Product rule:
If the user can see a number, they should be able to click it and see exactly what created that number.

Do not modify unrelated modules.
Do not weaken permissions.
Do not fake data.
Do not return unpaginated giant datasets.

2. Reusable drilldown component strategy

Reuse or generalize the MarketingDrilldownSheet if possible.

Preferred:
- rename/generalize to something like UniversalDrilldownSheet or MetricsDrilldownSheet
- keep Marketing-specific badge rendering where needed
- allow module-specific endpoint and columns

If generalizing is risky, create:
- PipelineDrilldownSheet
- InsightsDrilldownSheet

But avoid duplicating too much logic.

Each drilldown sheet should support:
- title
- metric description
- total count/value
- active filters
- searchable table
- sorting where practical
- pagination
- loading/error/empty state
- refresh button
- links to underlying records
- safe quick actions where existing patterns support them

3. Backend endpoints

Add endpoints or reuse existing patterns.

Preferred:
GET /api/pipeline/drilldown
GET /api/insights/drilldown

Query params:
- module
- metric
- segment
- status
- owner_id
- rep_id
- account_id
- lead_id
- campaign_id if relevant
- date_from
- date_to
- page
- page_size
- search
- sort
- extra filters as needed

Response:
- title
- description
- total
- filters
- columns
- rows
- pagination
- available_actions

Requirements:
- require auth
- enforce existing CRM/Insights permissions
- paginate always
- return only data the user is allowed to see
- never return massive unpaginated lists

8. Clickable charts

Any chart in Pipeline/Insights should support segment/point drilldown where possible:
- bar segment
- line point
- funnel stage
- pie segment
- source attribution bar
- forecast point
- risk segment

Clicking should open the drilldown sheet filtered to that segment.

9. Zero-count behavior

Even zero-count cards should open a useful empty state where practical.

Example:
No stalled deals = “No stalled deals. Pipeline is moving.”

Do not leave dead cards.

10. Visual affordance

Clickable metrics should look clickable:
- cursor pointer
- hover state
- subtle focus ring
- “View details” hint where appropriate
- keyboard accessible
- aria labels

Do not make the UI noisy.

11. Data integrity

Drilldown total should match visible card count.

If the count is cached or computed differently:
- refresh on drawer open
- show last refreshed timestamp if available
- log mismatch in dev
