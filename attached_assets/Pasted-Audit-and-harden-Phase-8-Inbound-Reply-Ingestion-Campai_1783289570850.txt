2. Matching Logic Audit

Audit matchInboundReplyToCampaignRecipient().

Verify matching priority order is exactly:

1. provider_thread_id
2. In-Reply-To
3. References
4. from_email + normalized subject + 30-day window + unambiguous only

Check:

* thread ID match requires sender email to match the campaign recipient or known contact where possible
* In-Reply-To and References parsing handles angle brackets, whitespace, comma/space-separated references
* subject normalization strips Re:, Fwd:, extra whitespace, and case differences
* fallback matching refuses ambiguous matches
* fallback matching refuses old sends outside 30 days
* fallback matching refuses mismatched sender emails
* fallback does not match on subject alone
* no @voltsafe.com / @voltsafe.test inbound gets processed
* matching never guesses when uncertain

3. Idempotency Audit

* same inbound provider_message_id processed twice does not create duplicate tasks
* same unmatched provider_message_id does not create duplicate unmatched records
* retrying unmatched replies does not create duplicate matched records
* scanRecentInboundReplies is idempotent
* Gmail incremental fire-and-forget hook is safe if the same email is seen again
