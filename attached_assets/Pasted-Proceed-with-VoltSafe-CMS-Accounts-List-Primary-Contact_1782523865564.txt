Proceed with VoltSafe CMS Accounts List Primary Contact Click-Through only.

Do not work on Currents, Training Hub, AI summaries, task features, Guest Currents, direct messages, workflow automation, or unrelated CRM features.

Goal

Make the Primary Contact name in the Accounts list clickable so users can jump directly to that contact’s profile/detail, without accidentally opening the Account detail row.

The Primary Contact column already exists and is audited. This task should only add click-through behavior.

Scope

Work only on:

1. Accounts list Primary Contact cell
2. Contact profile/detail navigation behavior
3. Minimal state/modal wiring if needed

Do not change backend payload unless the contact ID is missing. The primary contact payload already includes id.

Requirements

Click behavior

When an account has a primary contact:

* Contact name should be visually clickable.
* Clicking contact name should open that contact’s profile/detail.
* It should not also trigger the account row click.
* Use event.stopPropagation() to prevent the account detail row from opening.

When an account has no primary contact:

* Keep existing muted No primary contact fallback.
* No click behavior.

Preferred navigation

Use the existing contact detail behavior already used elsewhere in the app.

Before coding, audit:

* Contacts page contact detail pattern
* Contact profile route
* Existing contact detail dialog/modal if any
* Existing navigation helper for contacts
* Current router behavior

Preferred options, in order:

1. Open existing Contact detail dialog/modal if there is a reusable pattern.
2. Navigate to existing contact profile route, e.g. /contacts/:id, if that is the standard.
3. If neither is clean, make the contact name display-only and document why.

Do not build a new contact modal.

UI requirements

* Contact name should look like a subtle link:
    * underline on hover, or primary color on hover
    * cursor pointer
* Keep title text non-clickable unless easiest to include with the name.
* Do not clutter the row.
* Dark mode should look good.
* Keyboard/focus accessibility should be reasonable if using a button/link.
