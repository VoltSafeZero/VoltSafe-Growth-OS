All done. The fix is in place and all 38 regression tests pass.

What was fixed:

Root cause — Google Calendar populates event.location with a display-masked Zoom URL (us02web.zoom.us/j/******617) instead of the real meeting ID. When an event lacked conferenceData, the backend stored null for meetingUrl, so the frontend fell back to event.location, picked up the masked URL, and used it as the href — which Zoom rejects with "Invalid meeting ID (3,000)".

Two layers of defence added:

server/calendar-sync.ts — a new VALID_ZOOM_RE (requires /j/\d{9,12}(?!\d)/) and helper functions. The meetingUrl extraction now:

Validates the conferenceData URI has a full numeric meeting ID (rejects masked ones)
Falls back to hangoutLink (Google Meet)
Extracts a valid Zoom URL from event.location as a fallback
Extracts from event.description as a last resort
Never stores a masked URL
client/src/pages/calendar.tsx — detectMeetingProvider now validates any Zoom URL it finds has a numeric-only meeting ID. If masked, it returns { provider: "zoom", joinUrl: null, zoomMasked: true }. The Join Zoom button renders a grey "Zoom link unavailable" pill instead of a broken anchor when this happens.

Existing events with masked URLs already in the DB will now correctly show "Zoom link unavailable" — better than silently opening Zoom with an invalid ID. They'll self-heal on the next calendar sync once Google provides the full conferenceData.
