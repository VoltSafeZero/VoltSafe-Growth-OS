Proceed with VoltSafe CMS CURRENTS Workspace Experience Phase 5A: Dedicated CURRENTS Page + Futuristic Waterflow Backdrop.

Do not perform unrelated sidebar restructuring. Do not change CURRENTS messaging logic unless required for layout integration. Do not touch Gmail/mail-permissions, CRM behavior, Polyweather, or unrelated modules.

Goal

Transform CURRENTS from a normal Work subpage into its own premium, dedicated workspace experience — similar in importance to VoltSafe Mail.

CURRENTS should open into its own unique page/shell and feel like a core VoltSafe operating layer for internal communication.

Make it visually excellent.

Product intent

CURRENTS is VoltSafe’s internal communications layer — our own native Slack-like workspace inside VoltSafe CMS.

It should feel:

* premium
* futuristic
* marine/electrical
* alive, but not distracting
* distinctly VoltSafe
* clearly separate from ordinary CRM/work pages

Think:

“VoltSafe’s internal team current — information flowing across the company.”

Required experience

When a user opens CURRENTS:

1. They should enter a dedicated CURRENTS workspace page/shell.
2. The page should not feel like a regular CMS form/table page.
3. There should be a custom CURRENTS-themed backdrop.
4. The backdrop should show a futuristic water-flow / energy-flow animation for the first few seconds.
5. The animation should then stop or settle so users can work without distracting movement.
6. The CURRENTS chat/channel UI should remain fully usable and readable.
7. Existing CURRENTS functionality must remain intact.

Visual theme

Create a backdrop / screensaver-style environment inspired by:

* futuristic marina water at night
* digital current flow
* subtle cyan/teal electrical energy
* soft wave interference
* prongless power / smart shore power
* deep navy / black marine background
* luminous water ripples
* gentle flowing current lines
* premium SaaS command-center feel

Avoid:

* cheesy ocean clip-art
* loud neon overload
* constant movement while working
* low contrast text
* anything that makes chat hard to read

Animation behavior

The background animation should:

1. Play automatically when the CURRENTS workspace loads.
2. Ebb and flow for approximately 3–6 seconds.
3. Gradually settle/fade into a mostly static background.
4. Stop continuous animation after settling.
5. Respect reduced-motion preferences.
6. Not keep consuming unnecessary CPU/GPU after the intro finishes.
7. Not interfere with typing, scrolling, channel switching, uploads, or message actions.

Implementation options:

* CSS keyframes only, preferred if sufficient.
* Canvas only if there is already a safe lightweight pattern.
* No heavy animation libraries unless already installed.
* No backend dependency.
* No video asset unless absolutely necessary.

Audit the current CURRENTS route/page first.

Preferred approach:

1. Keep the existing CURRENTS route unchanged if possible.
2. Wrap the existing CURRENTS app/page in a new CurrentsWorkspaceShell.

    * custom full-page background

    * content container that preserves existing CURRENTS layout
