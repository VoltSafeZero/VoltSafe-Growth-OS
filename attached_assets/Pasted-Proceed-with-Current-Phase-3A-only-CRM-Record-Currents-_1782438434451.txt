Proceed with Current Phase 3A only: CRM Record Currents.

Goal:
Add record-specific Current feeds to VoltSafe CMS so team conversations can live directly inside CRM records such as Accounts, Leads, Contacts, Opportunities/Deals, and Tasks.

This is not a new chat system. Reuse the existing Current infrastructure wherever possible.

Do not add Guest Currents, direct messages, attachments, search, AI summaries, slash commands, or external collaborators yet.

Phase 3A scope

Add only:

1. Record-specific Current feeds
2. Current tab or section inside key CRM records
3. Backend routes for record Current messages
4. Reuse existing Current message features where practical:
    * posting
    * reactions
    * edit/delete
    * pins if easy
    * threads
    * @mentions
    * notifications
5. Deep-link support to record Current messages if reasonable

Important product language

Use the name Current consistently.

Do not call the tab “Discussion” long-term.

Examples:

* Account → Current
* Lead → Current
* Contact → Current
* Opportunity → Current
* Task → Current

Backend requirements

1. Use existing current_messages

If possible, use the existing object_type and object_id fields on current_messages.

Record Current messages should have:

* channel_id = null
* object_type = 'account' | 'lead' | 'contact' | 'opportunity' | 'task'
* object_id = record id
* parent_message_id = null for root messages
* parent_message_id = root message id for thread replies

If object_type or object_id fields do not exist, add them idempotently.

2. Add record routes

Add routes under /api/current/record:

* GET /api/current/record/:objectType/:objectId/messages
* POST /api/current/record/:objectType/:objectId/messages
* POST /api/current/record/:objectType/:objectId/read
* GET /api/current/record/:objectType/:objectId/pins if pins are reused

Messages should support:

* author info
* body
* timestamp
* edited/deleted state
* reactions
* reply count
* latest reply timestamp
* mention rendering/notification support

3. Thread replies for record messages

Existing thread routes should work for record Current messages too.

Verify:

* GET /api/current/messages/:id/thread
* POST /api/current/messages/:id/thread

For record messages, thread replies should inherit:

* same object_type
* same object_id
* channel_id = null

Do not accidentally require channel_id for thread replies.

4. Mentions and notifications

Record Current messages should support @mentions exactly like channel messages.

Notification action URL should point back to the record Current location if possible.

Example preferred URLs:

* /accounts/123?tab=current&message=456
* /accounts/123?tab=current&thread=456&message=789

Use the actual existing route structure in VoltSafe CMS. Do not invent routes that do not exist.

If deep-linking to the exact tab is risky, at minimum link to the record page and document the limitation.

5. Unread/read support

Add per-user read tracking for record Currents using the existing current_read_receipts table if possible.

Record read receipts should use:

* user_id
* object_type
* object_id
* last_read_message_id

Opening a record Current tab should mark it read.

Frontend requirements

1. Create reusable Current feed component

Refactor carefully if needed.

The same core feed should support two modes:

1. Channel mode:
    * /current
    * channelSlug
2. Record mode:
    * embedded inside CRM record page
    * objectType
    * objectId

Avoid duplicating a giant second copy of the Current UI. Keep it maintainable.

2. Add CurrentTab component

Create something like:

<CurrentTab objectType="account" objectId={account.id} />

It should show:

* compact Current feed
* messages
* composer
* reactions
* edit/delete
* threads
* @mentions
* pins if supported
* clean empty state

It should feel native inside the record page, not like an iframe dropped from space.

3. Add Current tab/section to CRM records

Add Current to the most important records first:

* Account profile
* Contact profile
* Opportunity/Deal profile
* Lead detail/drawer/page
* Task detail/drawer/page if straightforward

If all five are too much for one pass, prioritize:

1. Account
2. Lead
3. Contact
4. Opportunity/Deal
5. Task

Do not break existing tabs/pages.

4. UI/UX requirements

Record Current should feel slightly more compact than the main /current channel page.

Requirements:

* Premium dark mode
* Clean empty state
* Composer anchored cleanly
* No layout overflow
* No weird nested scroll traps
* Thread panel/drawer works inside record context
* Mention dropdown is not clipped
* Emoji picker is not clipped
* Pins do not dominate
* Existing record page layout remains clean

5. Deep-link behavior

If feasible, support deep links to record Current messages.

Examples depend on actual route structure.

Desired behavior:

* Record opens
* Current tab becomes active
* Target message scrolls into view
* Highlight ring appears briefly
* If thread param exists, thread panel opens

If this is too risky, implement basic record link only and document follow-up.
