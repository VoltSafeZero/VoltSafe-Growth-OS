Fix the Task Hub task modal dropdown scrolling bug.

Problem:
In the task detail modal, the Assignee dropdown and Shared users dropdown open correctly, but users cannot scroll down inside the dropdown list to select people lower in the list. This happens for:
1) Assignee selector
2) Shared / participant selector

Observed UI:
- Assignee dropdown shows users like Advisor Test, Alexandra Ruiz, George Al-Haddad, etc.
- Shared dropdown shows current shared users and add-participant list.
- The dropdown/list appears visually, but mouse wheel / trackpad scrolling does not work or is blocked by the modal/page scroll handling.

Required fix:
1) Make the dropdown menus internally scrollable.
2) Ensure mouse wheel / trackpad scroll events inside the dropdown are not swallowed by the modal overlay, dialog body, or parent scroll lock.
3) Set a sensible max height on each dropdown menu, for example:
   - max-h-[280px] or max-height: 280px
   - overflow-y-auto
   - overscroll-contain
4) Ensure the dropdown can scroll even when it is rendered inside the task modal.
5) Do not close the dropdown when the user scrolls inside it.
6) Do not allow the background/modal body to steal the scroll while the pointer is over the dropdown.
7) Keep keyboard accessibility working: arrow keys, Enter, Escape, and tab focus should still behave correctly.
8) Apply the same fix pattern to both Assignee and Shared participant dropdowns, preferably through a shared dropdown/list component if one exists.
