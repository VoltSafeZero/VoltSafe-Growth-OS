You are working on VoltSafe CMS / Growth OS.

Problem:
The Lead / Account sidebar edit forms have redundant marina data fields that are confusing users and creating dirty CRM data.

Example from Oak Bay Marina Lead:
The edit Lead page currently shows multiple overlapping fields for the same concepts:
- Slips
- Slip Count (exact)
- Est. Slips
- Est. Slips Impacted
- Est. Pedestals
- Segment free-text field
- Market Segment dropdown

This is bad UX and bad CRM hygiene. Users should have one obvious place to enter each piece of information.

Goal:
Audit and clean up the Lead / Account / Marina CRM field model and edit UI so there is one canonical field per concept, while preserving existing data safely.

Do NOT delete data blindly.
Do NOT run destructive migrations.
Do NOT remove backend fields until data migration/aliasing is understood.
Do NOT break existing AI summaries, lead scoring, enrichment, ROI story, opportunity profile, or CRM cards.
Do NOT rename database columns casually if downstream code relies on them.
First make the UI sane, then map legacy fields behind the scenes.

Primary product direction:
For marina-related Leads/Accounts, use a single clean field taxonomy:

Canonical fields should be:

1. Marina size
- Canonical display field: Slip Count
- Meaning: actual number of slips at the marina, if known
- Example: 412
- This should replace/hide duplicate visible fields like:
  - Slips
  - Slip Count (exact)
  - Est. Slips
  - Est. Slips Impacted
unless those are truly separate concepts.

2. Estimated VoltSafe deployment size
- Canonical display field: Est. Pedestals
- Meaning: estimated number of VoltSafe pedestals/opportunities
- Example: 150
- This should be the only visible pedestal estimate field unless there is a clear need for more.

3. Shore power availability
- Canonical display field: Shore Power?
- Values: Yes / No / Unknown
- No duplicate fields.

4. Market Segment
- Canonical display field: Market Segment
- Type: dropdown/select
- Example values:
  - Marina
  - RV Park
  - Commercial Port
  - Yacht Club
  - Resort / Hospitality
  - Municipality
  - Utility / Energy
  - Other
- Remove or hide the free-text “Segment” field from the primary edit UI unless it serves a distinct purpose.
- If the old free-text segment has data, preserve it as legacy/internal or map it into notes/tags only after audit.

5. Slip Range
- Canonical display field: Slip Range
- Type: dropdown/select
- Example:
  - 0–50
  - 51–100
  - 101–300
  - 300–500
  - 500+
  - Unknown
- This is allowed because it is a category/bucket, not a duplicate of exact slip count.
- But it should be clearly secondary to exact Slip Count.

6. Source
- Canonical display field: Source
- Meaning: where the lead came from
- Example: marina_directory
- Keep this.

7. Deal / Financial
- Deal Amount
- Probability
- Est. Close Date
- Hardware $
- Software $
- Services $
- Primary Value Driver
- Competitors
- ROI Story
These are separate and can remain, but ensure Est. Slips and Est. Pedestals are not duplicated here if already shown under Marina Details / Deal Information.
