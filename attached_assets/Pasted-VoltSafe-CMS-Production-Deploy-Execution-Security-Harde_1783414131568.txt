VoltSafe CMS — Production Deploy Execution: Security-Hardened Release

Goal:
Deploy the completed security-hardened VoltSafe CMS build after Phases 15–18.

Do not add features.
Do not change permissions unless a real deploy-blocking issue appears.
Do not modify routes unless production smoke tests fail.
This is deploy execution and monitoring only.

Pre-deploy confirmed:
- npm run build is clean
- Phase 15 full-app security hardening tests pass
- Phase 16 high-risk action hardening tests pass
- Phase 17 high-risk action application tests pass
- Phase 18 security production launch tests pass
- Board Pack, Capital, Currents, Today, nav, and startup tests pass
- security-production-monitoring.md exists

- audit metadata strips sensitive keys
- high-risk confirmation dialogs are wired
- copy-only routes remain copy_only: true

Post-deploy monitoring:
Use docs/security-production-monitoring.md as the runbook.

Watch for:
- migration errors
- 500s on high-risk routes
- unexpected 401/403 spikes
- failed audit inserts
- Board Pack access issues
- Capital portal token errors
- Currents membership errors
- Gmail disconnect errors
- unexpected send/export/delete spikes

Rollback only if:
- login/session breaks
- Today or core CRM fails to load
- permissions expose restricted data
- high-risk routes produce widespread 500s
- audit migration blocks startup
- confirmation layer blocks critical admin operations

Do not rollback for:
- expected 403s
- one harmless missing audit event
- cosmetic confirmation issue
- copy button UX issue

Deliverable:
Report:
- deployment status
- build result
- migration result
- smoke test result
- route/access checks
- any production warnings/errors
- whether rollback is needed
