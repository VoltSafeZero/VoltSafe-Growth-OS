3. Reply Classification Service

Create:

server/services/campaign-reply-classifier.ts

Functions:

* classifyCampaignReply(input)
* classifyUnprocessedReplies(limit)
* getReplyClassification(id)
* listReplyClassifications(filters)
* markClassificationReviewed(id, userId)
* dismissClassification(id, userId)
* createTaskFromClassification(id, userId)

Classification should use deterministic rules first, AI second.

Rule-based examples:

* contains “unsubscribe”, “remove me”, “stop emailing” → unsubscribe
* contains “not interested” → negative
* contains “out of office”, “automatic reply” → out_of_office / auto_reply
* contains “talk to”, “contact”, “try [name]”, “wrong person” → referral or wrong_person
* contains “pricing”, “cost”, “budget” → pricing_question
* contains “technical”, “install”, “electrical”, “CSA”, “UL”, “wiring” → technical_question
* contains “procurement”, “RFP”, “tender”, “board”, “council” → procurement_question
* contains “book”, “call”, “meeting”, “demo”, “calendar” → meeting_request
* contains “interested”, “send more”, “tell me more” → interested
* contains “later”, “next year”, “not now”, “circle back” → not_now

AI fallback:
Use the existing OpenAI compatibility helper pattern.
Do not use bare max_tokens/temperature.
The AI prompt should be marina/VoltSafe specific.
Output strict JSON:
{
“classification”: “…”,
“confidence”: 0.0-1.0,
“sentiment”: “positive|neutral|negative|unknown”,
“objection_type”: “…”,
“recommended_action”: “…”,
“recommended_task_title”: “…”,
“recommended_task_body”: “…”
}

Fail safely:

* if AI fails, return unknown with low confidence
* do not block user workflow on AI failure
* do not log full sensitive reply bodies

6. Sales Task Automation

If the CRM task system exists, integrate with it.

Create tasks automatically or semi-automatically for high-intent classifications.

Recommended defaults:

* meeting_request → create task automatically
* interested → create task automatically
* pricing_question → create task automatically
* technical_question → create task automatically
* procurement_question → create task automatically
* referral → create task automatically
* not_now → create nurture task/reminder if task scheduling exists
* objection → create review/follow-up task
* unsubscribe/negative/out_of_office/auto_reply → do not create sales task automatically

Task examples:

* “Follow up: GM requested demo from Thunderbird Marina”
* “Send pricing info to Thunderbird Marina”
* “Technical follow-up: shore power install question”
* “Referral received: contact marina manager”
* “Nurture: circle back in 90 days”

If automatic task creation is too risky, create a review queue with a “Create Task” button first.

10. Heat Score Integration

Update Account Heat Score:

* interested reply: +20
* meeting_request: +30
* referral: +15
* pricing_question: +15
* technical_question: +12
* procurement_question: +12
* not_now: +5 but recommend nurture
* objection: +5 but flag risk
* negative: -15
* unsubscribe: -25
* out_of_office/auto_reply: 0

Avoid double-counting if generic replied event already gives +20. Either replace generic reply score with classification-based scoring or cap reply contribution.

11. Compliance / Safety

* process unsubscribe if not already processed

* mark recipient unsubscribed

* do not automatically suppress unless explicit unsubscribe language exists
* recommend human review

Do not send automated replies in this phase.
