5. Reply signal priority protection — updateScore() now uses a SQL CASE WHEN is_replied = true THEN 'replied' guard so subsequent open/click events never downgrade a pixel that has already been marked as replied.

6. Signal hierarchy enforced in the frontend — SignalBadge resolves: isReplied → "replied" overrides everything, then isHot → "hot", then the score-based level.
