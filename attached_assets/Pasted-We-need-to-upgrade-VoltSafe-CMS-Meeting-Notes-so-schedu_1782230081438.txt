- Location/provider text: Microsoft Teams Meeting

  - psylvia@portofsandiego.org
  - zbirming@portofsandiego.org
- The event body contains Microsoft Teams join details and a teams.microsoft.com meeting URL.
- Current Meeting Notes page shows too many generic “New Meeting Note” rows with statuses like Scheduled, Recording, Completed, Failed. This is wrong. Scheduled calendar meetings must create named meeting notes tied to the actual calendar event.

Build this as one clean feature, but do it safely and incrementally. Audit existing calendar, meeting notes, transcription, CRM relationship, and database code before editing anything.

Core product rule:
A scheduled calendar meeting should never become a mystery “New Meeting Note.”
It should become:

Calendar Event → AI Meeting Note → Recorder/Transcription → Summary → Action Items → CRM Intelligence

The Meeting Notes system must distinguish between:
1. Scheduled calendar-linked meeting notes
2. True ad-hoc meeting notes

Ad-hoc notes can remain “Ad-hoc Meeting Note” or “New Meeting Note” if no title exists.
Calendar-linked notes must always use the calendar event title.

3. Detect meeting provider and meeting URL

Implement a shared utility function for parsing calendar event body/location/description/conference fields.

Detect:

- microsoft_teams if text contains teams.microsoft.com or “Microsoft Teams Meeting”
- zoom if text contains zoom.us or “Zoom Meeting”
- google_meet if text contains meet.google.com or “Google Meet”
- phone if text contains dial-in, phone conference, tel:, conference ID, or similar
- unknown if none detected
- adhoc for non-calendar notes

Extract meeting_url:
- Prefer actual calendar conference/link field if available
- Otherwise parse first valid meeting join URL from description/body/location
- For Teams, extract the teams.microsoft.com/l/meetup-join or teams.microsoft.com/meet URL
- For Zoom, extract the zoom.us/j or company.zoom.us/j URL
- For Google Meet, extract meet.google.com URL

For the screenshot example, the system should detect:

meeting_provider = microsoft_teams
meeting_url = first valid Teams join URL from the event body

4. Auto-create or update scheduled meeting note records

When calendar events are synced, opened, or loaded, ensure a meeting note record exists for scheduled events that have:
- a start time
- a title
- and either attendees or a meeting URL/conference/location/body

This must be idempotent:
- If a note already exists for account_id + calendar_event_id, update it with latest title/time/provider/url/attendees.
- Do not create duplicates.
- Do not overwrite completed transcript/summary/action_items unless explicitly regenerating.
- Do not overwrite manually edited notes if such edit tracking exists.

Meeting note title:
- For calendar-linked notes, always use the calendar event title.
- Never default to “New Meeting Note” when calendar_event_id exists and event title exists.

5. Auto-record scheduling behaviour

Minimum viable version:
At meeting start time, if auto_record_enabled = true:
- Create/activate the meeting note session
- Show an in-app notification/banner/toast:
  “[Meeting Title] is starting.”
  Buttons:
  - Start Transcription
  - Join Meeting
  - Snooze 5 min / Dismiss if existing notification patterns support it

If browser/device permissions are already granted and existing recorder supports automatic start, start recording.
If permissions are not granted, do not silently fail. Show:
“Recording requires microphone/system audio permission. Click Start Transcription.”

Important browser limitation:
Browser apps cannot reliably capture audio from Zoom, Teams, Google Meet, iMessage, WhatsApp, etc. automatically without user permission or provider-specific integrations. So the MVP must be honest:
- Support mic capture
- Support browser tab/system audio only where supported
- Support manual Start Transcription
- Support post-meeting upload/import if already available or easy to wire
- Do not claim full bot-level auto-join recording unless that integration actually exists

Future provider bots can come later:
- Zoom bot/app
- Microsoft Teams Graph/bot
- Google Meet bot
- Native desktop helper

For now, implement:
- calendar-linked notes
- auto-created scheduled notes
- provider detection
- start-at-meeting-time prompt
- manual/browser-based recording/transcription
- post-meeting summary
- CRM linking

11. Permissions and failure states

Be painfully clear in the UI.

If auto-start fails because browser permission is missing:
- Show status: “Permission required”
- Show CTA: “Start Transcription”

If provider URL is missing:
- Show: “No meeting link found”
- Still allow mic-based recording if meeting is in person/phone/ad-hoc

If transcription service fails:
- Show status: “Failed”
- Store error_message
- Allow retry

If user joins late:
- Still allow starting recording mid-meeting

If meeting is cancelled:
- Mark linked note as cancelled or hide from active scheduled list, depending existing calendar behavior

12. Acceptance criteria

Calendar modal:
- Every scheduled calendar event has an AI Meeting Notes section.
- User can enable/disable auto-record.
- User can start recording manually.
- User can open linked meeting note.
- User can join meeting if URL exists.
- Meeting provider is detected from event body/location/conference data.

Meeting Notes page:
- Scheduled notes show actual calendar event titles.
- Ad-hoc notes remain clearly labeled as ad-hoc.
- No duplicate notes are created on calendar sync/load/open.
- Statuses are accurate: scheduled, recording, processing, completed, failed.
- Existing generic “New Meeting Note” issue is fixed for calendar-linked notes.

Recording:
- If auto-record is enabled, system attempts to activate at meeting start time.
- If permission is required, user gets a clear prompt.
- Recording state only appears when real audio/transcription is active.
- Failed/pending states are visible and recoverable.

CRM:
- Meeting note links to attendees by email.
- External domains link to company records where possible.
- Meeting summary can appear in relationship timeline where supported.

Safety:
- No destructive migrations.
- No duplicate meeting notes.
- No fake recording states.
- Existing ad-hoc meeting notes still work.
- Existing completed meeting notes are not overwritten.
- Tests added or updated for provider detection, idempotent note creation, scheduled note naming, and status transitions.
