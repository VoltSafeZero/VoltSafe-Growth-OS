VoltSafe CMS — CEO Cockpit Phase 7: Operating Cadence, Weekly Review, and CEO Briefing

Goal:
Turn the CEO Cockpit + Action Queue into a repeatable operating cadence:
- daily CEO briefing
- weekly leadership review
- accountability history
- missed commitments
- wins and momentum
- unresolved blockers
- team/member follow-up summaries
- safe draft outputs only, never auto-send

Context:
Phase 4 built the CEO Cockpit insights.
Phase 5 built 1:1 notes, agendas, commitment extraction, and reviewed task creation.
Phase 6 built the CEO Action Queue and controlled follow-up loop.

Now build Phase 7 as an operating layer on top of those systems.

Core requirements:

1. CEO Briefing service
Create:

server/services/ceo-briefing.ts

Functions:

- buildDailyCeoBriefing(actorUser, options)
  Returns a deterministic daily briefing from local DB only.

- buildWeeklyCeoReview(actorUser, options)
  Returns a deterministic weekly review from local DB only.

- buildTeamMemberBriefing(memberUserId, actorUser, options)
  Returns a per-person summary for 1:1 prep and leadership accountability.

- buildLeadershipMeetingAgenda(actorUser, options)
  Builds a structured leadership meeting agenda from blockers, action queue, commitments, stale work, upcoming deadlines, and wins.

No external API calls.
No OpenAI dependency required.
No auto-send.

2. Daily CEO Briefing output
Daily briefing should include:

- overnight changes
- new blockers
- unresolved critical/high actions
- overdue tasks
- stale opportunities
- commitments due soon
- 1:1s today / tomorrow
- Currents hotspots
- CEO-owned items
- capital-sensitive section only if user has capital permission
- recommended top 5 CEO actions for today

Each section must have:
- title
- severity: info | watch | urgent | critical
- items array
- empty_state
- reason text in plain English

3. Weekly CEO Review output
Weekly review should include:

- completed actions
- dismissed actions
- snoozed actions
- unresolved actions
- blockers opened / resolved
- overdue tasks by owner
- commitments created / completed / missed
- team pulse movement
- sales/opportunity movement
- capital movement if permitted
- communication hotspots
- top wins
- top risks
- suggested leadership meeting agenda

Include date range support:
- default: last 7 days
- allow startDate / endDate query params

4. Team member briefing
For each internal team member, return:

- current signal label
- active tasks
- overdue tasks
- blocked tasks
- commitments from 1:1s
- open CEO action queue items involving that person
- recent wins
- recent silence/staleness
- suggested 1:1 talking points
- suggested support questions

Must not shame people.
Use neutral operational language:
- “Needs check-in”
- “Blocked”
- “Quiet”
- “Momentum”
- “Follow-up suggested”

Avoid:
- lazy
- failing
- poor performance
- blame language

5. Leadership meeting agenda
Build a structured agenda:

Sections:
- Decisions needed
- Blockers to clear
- Commitments due
- Customer/revenue movement
- Capital/funding movement if permitted
- Product/operations risks
- Team support
- Wins
- Follow-ups from last meeting

Each item should include:
- title
- owner
- source
- why it matters
- suggested discussion prompt
- linked action/task/source metadata where available

6. API routes
Add requireAuth + requireAdmin routes:

GET /api/today/ceo-briefing/daily
GET /api/today/ceo-briefing/weekly
GET /api/today/ceo-briefing/team-member/:userId
GET /api/today/ceo-briefing/leadership-agenda

Optional safe draft routes:

POST /api/today/ceo-briefing/weekly/draft
POST /api/today/ceo-briefing/leadership-agenda/draft

Draft routes return copyable text only.
They must not send Currents messages.
They must not send email.
