Please perform a Currents Phase 6B View in Currents audit and polish pass only.

Do not add Guest Currents, direct messages, slash commands, external collaborators, workflow automation, Mark as Decision/Risk/Requirement, or unrelated task features yet.

Goal

Verify that tasks created from Currents reliably show the correct source context and deep-link back to the exact Currents message/thread/record.

Audit scope

Audit only:

1. Currents source block in the task detail drawer
2. View in Currents link generation
3. Task metadata interpretation
4. Deep-links back to channel Currents
5. Deep-links back to Record Currents
6. Existing task and Currents regressions caused by Phase 6B

Metadata audit

Inspect real task records created from Phase 6A and verify how metadata is stored and returned by the task APIs.

Check:

* source
* source_label
* source_meta
* sourceContext
* messageId
* channelSlug
* threadRootId
* objectType
* objectId
* summaryContext
* linkedObjectType
* linkedObjectId

Confirm which fields are returned as snake_case vs camelCase in the frontend task drawer.

Task drawer UI checks

Verify:

1. Tasks without Currents metadata do not show the source block.
2. Tasks with Currents metadata show a compact source block.
3. Source block appears in a sensible location.
4. Source block looks good in dark mode.
5. Channel task shows the channel name, e.g. #general.
6. Channel thread reply task shows clear thread/reply context.
7. Record task shows the record type and id/name if available.
8. AI summary action item task shows useful context if supported.
9. The link label is clear:
    * View in Currents
10. Link does not look like an external website link if it stays inside the app.
11. No layout crowding inside the drawer.

Deep-link rules to verify

Channel top-level message

Task metadata:

* sourceContext = "currents_channel"
* channelSlug
* messageId
* no threadRootId

Expected link:

/current?channel=CHANNEL_SLUG&message=MESSAGE_ID

Verify it opens:

* Correct channel
* Correct message
* Highlight target if supported

Channel thread reply

Task metadata:

* sourceContext = "currents_channel"
* channelSlug
* messageId
* threadRootId

Expected link:

/current?channel=CHANNEL_SLUG&thread=THREAD_ROOT_ID&message=MESSAGE_ID

Verify it opens:

* Correct channel
* Thread panel
* Correct reply context
* Root highlight behavior works as intended

Account Currents message

Expected link:

/accounts/OBJECT_ID?tab=current&message=MESSAGE_ID

Verify:

* Account page opens
* Currents section/tab is visible
* Target message highlights if supported

Account Currents thread reply

Expected link:

/accounts/OBJECT_ID?tab=current&thread=THREAD_ROOT_ID&message=MESSAGE_ID

Verify:

* Account page opens
* Thread panel opens if supported
* Correct message/reply context is visible

Contact Currents message/thread

Use the actual existing Contact route.

Verify:

* Contact page opens
* Currents tab/section opens
* Message/thread context works

Opportunity Currents message/thread

Use the actual existing Opportunity route.

Verify:

* Opportunity page opens
* Currents section opens
* Message/thread context works

Lead Currents message/thread

Must use corrected Lead route:

/opportunities?selected=LEAD_ID&tab=current&message=MESSAGE_ID

Thread reply:

/opportunities?selected=LEAD_ID&tab=current&thread=THREAD_ROOT_ID&message=MESSAGE_ID

Verify:

* Leads page opens
* Correct lead detail/dialog opens
* Currents view is active
* Message/thread context works
