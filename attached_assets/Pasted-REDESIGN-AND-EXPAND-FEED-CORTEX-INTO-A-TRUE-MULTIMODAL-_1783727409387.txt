REDESIGN AND EXPAND “FEED CORTEX” INTO A TRUE MULTIMODAL KNOWLEDGE INGESTION HUB.

CURRENT PROBLEM

Feed Cortex currently looks polished, but functionally it only accepts pasted URLs.

That is far too limiting.

Cortex must be able to ingest knowledge in any useful form:

- URL
- pasted text
- documents
- images
- video
- audio
- live voice recording
- screen capture or screenshots
- drag-and-drop files
- multiple files at once

The redesigned page must make these options immediately obvious, visually engaging, simple, and trustworthy.

Do not remove the current Cortex visual identity. Evolve it into something cleaner, more powerful, and more intuitive.

==================================================
1. CORE PRODUCT GOAL
==================================================

A user should land on Feed Cortex and instantly understand:

“I can teach Cortex anything, in almost any format.”

The page should feel like a futuristic knowledge intake console, not a plain upload form.

Every ingestion method must feed the same verified backend pipeline:

Input
→ upload or capture
→ extract content
→ analyze
→ chunk
→ index
→ verify retrieval
→ mark ready
→ make available to Cortex

Do not create fake UI controls that are not wired to working ingestion.

==================================================
2. REDESIGN THE MAIN FEED CORTEX INTERFACE
==================================================

Keep the current:

- Feed CORTEX title
- VoltSafe Intelligence Layer identity
- central Cortex visual
- clean white/light visual style
- teal accents
- “What Cortex Learned Today”
- ingestion history
- Ask Cortex

Improve the main ingestion area substantially.

Replace the single URL input with a visually prominent multimodal ingestion panel.

Suggested structure:

FEED CORTEX

“Teach Cortex anything. Add a link, paste text, upload a file, show it an image, or speak directly.”

Under this, show six clear ingestion cards or tiles:

1. Add a Link
   Icon: globe/link
   Text: “Paste a webpage, article, YouTube video, cloud document, or other URL.”

2. Paste Text
   Icon: text/document
   Text: “Paste notes, research, meeting summaries, emails, ideas, or raw knowledge.”

3. Upload Files
   Icon: upload/folder
   Text: “Add PDFs, Word documents, spreadsheets, presentations, and other files.”

4. Add Images
   Icon: image/camera
   Text: “Upload screenshots, diagrams, charts, product photos, and scanned documents.”

5. Add Video or Audio
   Icon: play/waveform
   Text: “Upload recordings, presentations, interviews, webinars, or training videos.”

6. Speak to Cortex
   Icon: microphone
   Text: “Record a voice note and teach Cortex directly.”

These should not look like six boring form buttons.

Use:

- clean cards
- subtle shadows
- hover lift
- animated Cortex-style glow
- clear iconography
- drag-and-drop interaction
- concise descriptions
- strong selected state
- responsive layout

On desktop, use a 3 × 2 grid or similarly balanced layout.

On smaller screens, stack intelligently.

3. UNIVERSAL DRAG-AND-DROP ZONE
==================================================

Add a large universal drop zone below or integrated with the input cards:

“Drop anything here to feed Cortex”

Supporting text:

“Documents, images, video, audio, or multiple files”

The drop zone should:

- highlight on drag-over
- show accepted formats
- support multiple files
- show file thumbnails or icons
- detect file type automatically
- route each file into the correct ingestion pipeline
- reject unsupported files clearly
- enforce file-size limits
- show per-file progress

Users should also be able to click the drop zone to browse files.

==================================================
4. INPUT-SPECIFIC EXPERIENCES
==================================================

Each ingestion card should open the correct interaction.

A. ADD A LINK

Provide:

- URL input
- paste-from-clipboard support
- URL validation
- detected source type
- title preview
- site icon/domain
- current ingestion status
- Feed Cortex button

Support, where technically and legally possible:

- normal webpages
- articles
- YouTube
- Vimeo
- public Google Docs
- public Dropbox links
- PDFs by URL
- LinkedIn pages when accessible
- other public media URLs

Do not mark a source as learned unless actual content was extracted and indexed.

B. PASTE TEXT

Provide a large text composer with:

- title field
- text body
- character count
- optional source/context field
- optional tags
- paste formatting cleanup
- plain-text fallback
- Markdown support where practical
- Save and Feed Cortex button

Allow users to paste:

- meeting notes
- emails
- research
- technical findings
- customer feedback
- strategy notes
- procedures
- copied article text
- product requirements

C. UPLOAD FILES

Support at minimum:

- PDF
- DOCX
- TXT
- CSV
- XLSX
- PPTX
- Markdown
- common office-document formats already supported by the codebase

For each file:

- show filename
- file type
- size
- extraction status
- page or sheet count where available
- extracted character count
- chunk count
- retrieval-ready status

D. ADD IMAGES

Support:

- PNG
- JPG/JPEG
- WebP
- screenshots
- photographed documents
- diagrams
- charts
- whiteboards
- scanned pages

Image ingestion should include:

- visual analysis
- text extraction
- description
- key objects or subjects
- chart or diagram interpretation where supported
- generated summary
- original image retention
- extracted text preview
- privacy and permission scope

Do not rely only on OCR. Preserve both the image and the model-generated visual understanding.

E. ADD VIDEO OR AUDIO

Support uploads such as:

- MP4
- MOV
- WebM
- MP3
- WAV
- M4A
- other formats supported by the existing media pipeline

For video:

- extract audio
- transcribe speech
- preserve timestamps
- sample important frames when useful
- analyze visible slides or screens
- produce a structured summary
- create retrievable transcript chunks
- link chunks to timestamps

For audio:

- transcribe
- identify speakers when supported
- retain timestamps
- summarize
- create searchable chunks

Show clear states:

- uploading
- processing
- transcribing
- analyzing
- indexing
- verifying
- ready
- failed

F. SPEAK TO CORTEX

Add a built-in voice recorder.

Controls:

- Start recording
- Pause
- Resume
- Stop
- Cancel
- Preview
- Re-record
- Feed Cortex

While recording, show:

- waveform
- timer
- microphone state
- recording indicator

After recording:

- transcribe the audio
- allow the user to edit the transcript
- allow a title
- allow tags
- show duration
- submit to Cortex

The recording must finish cleanly and display success. It must not remain stuck on a spinning loader after processing completes.

==================================================
11. DUPLICATE DETECTION
==================================================

Before ingesting:

- compare normalized URL
- compare file hash
- compare content hash
- compare prior source records

If a duplicate is detected, show:

“This appears to have already been fed to Cortex.”

Provide options:

- Open existing source
- Reprocess
- Create a new version
- Cancel

Do not silently create duplicate knowledge chunks.

==================================================
12. PERMISSIONS AND SECURITY
==================================================

Every ingested item must respect CMS permissions.

Allow the user to set visibility:

- Private to me
- My team
- Department
- Entire company
- Custom users

Default to the existing product permission rules.

All derived items must inherit the source permissions:

- extracted text
- transcript
- chunks
- summaries
- embeddings
- search results
- Cortex answers

Never allow another user to retrieve a source they cannot access.

Protect against:

- unsafe file types
- executable uploads
- oversized files
- malformed files
- malicious HTML
- prompt injection inside uploaded content
- cross-user retrieval
- private URL leakage
- duplicate processing attacks

Treat uploaded knowledge as source material, not system instructions.

==================================================
13. FILE LIMITS AND USER FEEDBACK
==================================================

Create practical configurable limits.

Display limits before upload.

For example:

- documents: configurable maximum
- images: configurable maximum
- audio/video: configurable maximum
- voice recordings: configurable duration
- total batch size: configurable maximum

Do not hardcode values in multiple components.

Use a central configuration.

When a limit is exceeded, explain exactly what must change.

Bad:

“Upload failed.”

Good:

“This video is 620 MB. The current upload limit is 500 MB.”
