6. SMART AUTO-ATTACHMENT / RELATIONSHIP LINKING SYSTEM
==================================================

This is a core feature and must be designed properly.

I want emails and threads to be smartly and automatically attached to the correct records inside VoltSafe Cortex, including:
- Accounts
- Leads
- Contacts
- Partners
- Opportunities/Deals
- Suppliers/Vendors where applicable
- Projects or other related entities if they exist in the data model

The system must not rely only on exact email match. It needs multi-layer smart linking.

AUTO-ATTACHMENT PRIORITY LOGIC

PRIORITY 1: EXACT CONTACT MATCH
- If sender or recipient email exactly matches an existing contact email, attach thread to that contact
- If that contact belongs to an account, also attach to that account
- If that contact belongs to a lead, also attach to that lead if lead record still active
- If that contact belongs to a partner organization, also surface that relationship

PRIORITY 2: ACCOUNT DOMAIN MATCH
- If no exact contact match exists, check sender domain and recipient domain
- If domain matches a known account domain, attach thread to that account
- If multiple records share the same domain, use strongest contextual match and lower confidence until reviewed

PRIORITY 3: LEAD DOMAIN OR LEAD EMAIL MATCH
- If thread participants match a lead email or lead company domain, attach to that lead
- If lead is later converted into account/contact, preserve historical linkage and map forward cleanly

PRIORITY 4: PARTNER DOMAIN OR KNOWN PARTNER CONTACT MATCH
- If domain or participant matches a known partner or partner contact, attach thread to that partner record

PRIORITY 5: OPPORTUNITY / DEAL INFERENCE
- If thread is already attached to an account/lead/contact and there is exactly one open relevant opportunity/deal, suggest or auto-link to that opportunity
- If there are multiple possible deals, show suggestions for user confirmation
- If subject line or labels contain strong signals like pilot, proposal, PO, quote, certification, grant, investor, etc., use those to rank related opportunities

PRIORITY 6: MANUAL REVIEW QUEUE
- If confidence is too low, place the thread in Unlinked or Needs Review
- Show best candidate suggestions with confidence score and reason

ADDITIONAL SMART LINKING RULES
- Support many-to-many linking where appropriate
- A thread may belong to a contact and account together
- A thread may also be attached to a partner, deal, or project if appropriate
- Preserve both primary record and secondary related records
- Maintain audit trail of how thread was linked: auto, suggested, or manual
- Allow manual override at any time
- Remember manual overrides and use them to improve future linking logic

SMART MATCHING SIGNALS TO USE
- exact email address
- alternate contact emails
- company domain
- known aliases/domains
- prior thread participants
- thread subject keywords
- reply chain history
- existing CRM ownership relationships
- linked calendar invite participants if available
- manual user corrections from past matches

CONFIDENCE MODEL
Each auto-attachment should have:
- confidence score
- match reason
- linked_by type: auto / suggested / manual / imported
- reviewed flag

Example confidence logic:
- exact contact email = very high confidence
- direct domain-to-account match = high confidence
- weak keyword-only match = low confidence
- multiple possible matches = suggestion only, not auto-finalize
