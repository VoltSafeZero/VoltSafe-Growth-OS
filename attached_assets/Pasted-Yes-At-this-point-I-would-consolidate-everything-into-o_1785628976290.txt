I think this version is stronger than the evolving prompts because it incorporates the critical corrections that emerged from the audits:

* It separates the audit from implementation.
* It avoids guessing schema or tenancy.
* It introduces an UNKNOWN state to avoid falsely showing “No Action Needed.”
* It uses waiting_since_at instead of created_at for immediate-due ordering.
* It requires SQL-based Smart Priority for scalability.
* It explicitly prevents imported prospect records from overwhelming the active work queue.
* It enforces phased checkpoints so you don’t pay for large rewrites if an early architectural assumption turns out to be wrong.
