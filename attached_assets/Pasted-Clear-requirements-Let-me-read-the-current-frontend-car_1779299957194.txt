Known Limitations
Gmail auto-sync email association: When the background Gmail sync automatically associates a new inbound email to a CRM record (via the email_associations table in the sync worker), the stale marking is not currently triggered — only manual email linking via the timeline UI is wired. The backfill's source hash check will catch this on the next scheduled regen, but there is no real-time hook into the sync worker. This is an acceptable trade-off; the backfill or next manual view will correct it.
Attachment deletion stale marking: DELETE /api/attachments/:id is not wired (the attachment row doesn't always carry the CRM objectType/objectId without a lookup). Minor gap — the backfill will re-evaluate on next run.
Backfill limits: The queries cap at 5,000 leads, 2,000 accounts, 5,000 contacts per run. With 10,962 leads in the DB currently, a second run is needed to cover the remainder if counts exceed those limits.
