4. Identity resolver integration

Update server/services/identity-resolver.ts and/or server/services/association-engine.ts so these identifiers act as authoritative signals before fuzzy matching.

Priority order:
1. Exact email match from crm_email_addresses
2. Domain match from crm_email_domains, excluding public domains
3. Existing fuzzy/domain scoring logic

Rules:
- Do not remove or rewrite existing fuzzy scoring.
- Do not change existing scoring weights unless absolutely necessary.
- New identifiers should short-circuit ambiguous fuzzy matching.
- Exact email match should win over domain match.
- Domain match should win over fuzzy match.
- Conflict prevention should make it impossible for the same domain/email to point to multiple CRM entities.
