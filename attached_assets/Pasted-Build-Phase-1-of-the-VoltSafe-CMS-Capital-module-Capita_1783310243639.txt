Build Phase 1 of the VoltSafe CMS Capital module: Capital CRM Foundation.

Context:
VoltSafe CMS already has a robust Marketing module. Now we need a focused Capital module to help VoltSafe identify, prioritize, pursue, track, and close funding from:

* Angels
* High-net-worth individuals
* Family offices
* Venture capital
* Strategic investors
* Government grants
* Government investment programs
* Accelerators/incubators
* Corporate venture groups
* Venture debt
* Climate/energy/marine infrastructure funders

Important product principle:
This module must not become bloatware. Build survival tooling, not a giant investor relations platform.

Goal:
Create the foundation for a Capital Command Center that answers:

* Who can fund us?
* Who should we chase?
* Who is warm?
* What do they need?
* What is due soon?
* What is blocking the money?
* How much capital is realistically in motion?

Do not build:

* full cap table management
* investor portal
* securities compliance automation
* financial model builder
* DocuSign clone
* complex fund accounting
* LP reporting
* campaign ROI attribution
* drag-and-drop workflows

3. Derived Fields / Calculations

Implement weighted_amount_cents:

weighted_amount_cents = expected_amount_cents × probability_percent / 100

This should update on create/update for funders and grants.

Do not overcomplicate this with forecasting yet.

4. API Routes

Add Capital API routes.

Dashboard:

* GET /api/capital/dashboard

Funders:

* GET /api/capital/funders
* POST /api/capital/funders
* GET /api/capital/funders/:id
* PATCH /api/capital/funders/:id
* DELETE /api/capital/funders/:id

Grants:

* GET /api/capital/grants
* POST /api/capital/grants
* GET /api/capital/grants/:id
* PATCH /api/capital/grants/:id
* DELETE /api/capital/grants/:id

Documents:

* GET /api/capital/documents
* POST /api/capital/documents
* PATCH /api/capital/documents/:id
* DELETE /api/capital/documents/:id

Activities:

* GET /api/capital/activities
* POST /api/capital/activities
* PATCH /api/capital/activities/:id
* DELETE /api/capital/activities/:id

Pipeline:

* GET /api/capital/pipeline

Route requirements:

* All routes require auth
* View routes require appropriate CRM/Capital view permission
* Create/update/delete routes require appropriate CRM/Capital edit permission
* Invalid IDs return clean 400/404
* Route errors do not leak stack traces
* Input payloads are validated
* Deleting records should be safe and should not crash on FK references

If there is no Capital permission yet, use the closest existing CRM permission pattern, but structure the code so a future capital permission can be added.
