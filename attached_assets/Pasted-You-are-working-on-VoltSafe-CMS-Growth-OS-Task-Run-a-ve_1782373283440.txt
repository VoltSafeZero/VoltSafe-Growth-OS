Implementation Phase 1 — Confirm before scheduling task blocks

If Schedule currently creates a calendar block immediately after picking a window, change it to a safer confirmation step.

Desired UX:

1. User clicks “Schedule” on a task.
2. Popover opens with suggested windows.
3. User selects a window.
4. Inline confirmation appears:
    * Task title
    * Selected date/time
    * Duration
    * Calendar destination if available
    * Button: “Create Focus Block”
    * Button: “Cancel”
5. Only after confirming should the Google Calendar event be created.

Do not make this a giant modal. Keep it compact.

Implementation Phase 2 — Clear write-scope / reconnect handling

Check whether the Google Calendar integration has write scope.

If write scope is missing:

* Do not show scheduling as if it will work.
* Disable or soften the Schedule button.
* Show:
    “Reconnect Google Calendar to enable task blocking.”
* Add action/link to Calendar Settings or Integrations.

If write scope exists:

* Scheduling may proceed.

If the backend route returns write-scope error:

* Show a clear toast.
* Do not leave UI in loading state.
* Do not create duplicate blocks on retry.

Implementation Phase 3 — Prevent duplicate focus blocks

Before creating a task calendar block:

* Prevent double-click duplicate creation in the UI.
* Disable confirm button while mutation is pending.
* If the task already appears scheduled in local state or route response, show “Scheduled” instead of “Schedule.”
* If no scheduledTask field exists, at least prevent duplicate creation during the current session using local component state keyed by task ID.

Do not add a migration unless there is already a task scheduling/status field available and unused.

Implementation Phase 4 — Better Focus Block details

When creating the Google Calendar event block, ensure it includes:

* Description:

    * Task ID if available
    * Related CRM record if available
    * Original due date if available
* Source/calendar: user’s primary or selected default calendar
