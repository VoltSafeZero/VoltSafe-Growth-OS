Build Phase 4 for the VoltSafe CMS Marketing / Campaigns module: Unsubscribe Handling + Open/Click/Reply Tracking.

Context:
Marketing Phases 1–3 are complete.

Already implemented:

* Campaign CRUD
* Campaign detail page
* Email sequence builder
* AI copywriting
* Templates
* Suppression list
* Audience segments
* Real recipient enrollment from CRM segments
* Recipient preview
* Suppression-safe enrollment
* Step-level send preview
* Manual campaign step sending
* Campaign event creation for send activity
* Recipient status progression
* Personalization fallback handling
* Duplicate-send protection
* Internal @voltsafe.com protection

Known remaining gap:
Campaigns can now send safely, but they do not yet track recipient engagement after sending. There is no unsubscribe handling, open tracking, click tracking, reply tracking, or account-level engagement heat.

Goal:
Implement safe engagement tracking for campaign emails:

* unsubscribe handling
* open tracking pixel
* click tracking redirects
* reply detection if existing mail infrastructure supports it
* campaign recipient engagement fields
* campaign analytics updates
* account/contact engagement rollups

Do not implement automated drip scheduling yet.

Core principle:
Every tracked engagement should tie back to:

* campaign_id
* campaign_email_id / step
* campaign_recipient_id
* contact_id
* account_id

1. Unsubscribe Handling

Add a unique unsubscribe token for each campaign recipient.

If the campaign_recipients table does not already have a token field, add:

* unsubscribe_token
* unsubscribed_at
* unsubscribe_reason if useful

Requirements:

* token must be unique
* token must not expose raw IDs
* token should be generated at enrollment or before sending
* unsubscribe links should be included in campaign emails
* unsubscribe should suppress the exact email globally using campaign_suppression
* recipient status should become unsubscribed
* campaign_event should record unsubscribed
* unsubscribe page should be simple, branded, and safe

Add endpoint:
GET /api/marketing/unsubscribe/:token

This should show a confirmation page or return the unsubscribe state.

Add endpoint:
POST /api/marketing/unsubscribe/:token

This should:

* validate token
* mark campaign_recipient unsubscribed
* add email to campaign_suppression
* create campaign_event event_type = unsubscribed
* return success

If the frontend routing pattern supports a public page, add:
/public/unsubscribe/:token
or equivalent route.

Do not require authentication for unsubscribe.

2. Open Tracking

Add open tracking pixel support.

When campaign email body is rendered for sending, append a tracking pixel:

/api/marketing/track/open/:token.gif

or similar.

Endpoint:
GET /api/marketing/track/open/:token.gif

This should:

* validate token
* ignore known internal/test user agents if possible
* ignore internal VoltSafe viewer activity if identifiable
* create campaign_event event_type = opened
* increment opened_count on campaign_recipients if field exists
* store metadata:
    * user_agent
    * ip hash if appropriate
    * timestamp
    * campaign_email_id / step if encoded or available
* return a transparent 1x1 GIF

Important:
Do not count @voltsafe.com internal opens if the opener can be identified. If not identifiable from pixel request alone, at minimum exclude obvious internal/test user agents.

3. Click Tracking

Rewrite campaign email links through a redirect endpoint before sending.

Add table if needed:
campaign_tracked_links:

* id
* campaign_id
* campaign_email_id
* campaign_recipient_id
* original_url
* tracking_token
* created_at

When rendering an email:

* find links in body_html
* replace each href with:
    /api/marketing/track/click/:trackingToken

Endpoint:
GET /api/marketing/track/click/:trackingToken

This should:

* validate token
* create campaign_event event_type = clicked
* increment clicked_count on campaign_recipients if field exists
* redirect to original_url
* reject unsafe redirect URLs such as javascript:, data:, file:
* preserve only safe http/https URLs

4. Reply Tracking

If existing VoltSafe Mail infrastructure can associate inbound replies to sent campaign messages, implement reply tracking.

Requirements:

* when a reply is detected, create campaign_event event_type = replied
* set campaign_recipients.replied_at
* optionally classify reply later via AI, but do not build full AI reply classifier unless simple
* update campaign analytics

If reply matching is not safely available yet, add a clear placeholder and report it as a remaining gap.

Possible matching methods:

* provider message ID
* thread ID
* campaign-specific reply-to tag
* custom header if mail infrastructure supports it
* subject/thread matching as fallback only if safe

10. Safety / Compliance

* unsubscribe must be one-click or very simple
* unsubscribe must not require login
* unsubscribe must globally suppress that email
* tracking endpoints must not expose private data
* click redirect must reject unsafe URLs
* open tracking must return valid transparent GIF
* missing/invalid tracking token should not crash
* repeated opens/clicks should be recorded but unique counts should be calculable
* do not log full email bodies in events
* do not include sensitive recipient data in public tracking responses
