Goal

Verify that Currents presence indicators are secure, stable, polished, and regression-free.

Backend route checks

POST /api/current/presence/heartbeat

Verify:

1. Requires authentication.
2. Uses session user ID only.
3. Cannot spoof another user via body/query params.
4. Stores only minimal data.
5. Uses correct key: presence:user:{userId}.
6. Uses 90-second TTL.
7. Refreshes TTL on repeated heartbeat.
8. Returns { ok: true }.
9. Does not expose user profile data.

GET /api/current/presence

Verify:

1. Requires authentication.
2. Accepts comma-separated userIds.
3. Sanitizes invalid IDs.
4. Rejects or ignores floats, strings, negatives, zero, empty values.
5. Caps at 100 user IDs.
6. Returns only { userId, status }.
7. Does not expose names, emails, roles, permissions, or private profile fields.
8. Returns online only if TTL entry exists.
9. Returns offline if missing/expired.
10. Handles empty/sanitized-out list cleanly.
11. Does not leak group/DM membership beyond requested IDs.

Cache / TTL checks

Verify:

1. TTL is 90 seconds.
2. Heartbeat every 30 seconds is sufficient.
3. Presence expires naturally after TTL.
4. Cache sweep prevents unbounded growth.
5. Repeated heartbeat keeps user online.
6. Presence cache does not persist across server restart, which is acceptable.
7. Presence keys cannot be created for arbitrary spoofed users.
8. Memory growth is bounded by active users.

Frontend checks

Heartbeat

Verify:

1. Heartbeat fires immediately when /current loads.
2. Heartbeat repeats every 30 seconds.
3. Heartbeat stops on unmount.
4. Heartbeat does not fire before current user ID is known.
5. Heartbeat does not spam on every render.
6. Heartbeat does not create console/server noise.

Presence query

Verify:

1. Query only includes visible/relevant users.
2. Query includes 1:1 DM other users.
3. Query includes group DM members.
4. Query dedupes IDs.
5. Query uses stable ordering.
6. Query is disabled when there are no IDs.
7. Polls every 30 seconds.
8. Uses refetchOnWindowFocus: false.
9. Does not query all users in the system.

DM sidebar

Verify:

1. 1:1 DM online dot appears when user is online.
2. Offline state does not cause layout shift.
3. Dot placement is clean on avatar.
4. Dot does not crowd unread/mute badges.
5. Dark mode styling is clean.
6. Group DM sidebar does not get cluttered.

DM/group DM header

Verify:

1. 1:1 DM header shows Online when online.
2. 1:1 DM header shows Offline when offline.
3. Group DM header shows N members · M online when M > 0.
4. Group DM header hides online count cleanly when M = 0.
5. Current user handling is intentional:
    * confirm whether current user counts toward group online count.
    * document the decision.
6. Header does not jump or wrap awkwardly.

GroupMemberDialog

Verify:

1. PresenceMap is passed correctly.
2. Current user row shows sensible status.
3. Other members show online dot/status when online.
4. Offline members still show readable email/details.
5. Existing add-member search still works.
6. Leave confirmation still works.
7. Dialog layout remains clean in dark mode and smaller screens.

Security/privacy checks

Verify:

1. User cannot spoof another user’s presence.
2. Presence GET does not leak emails, names, roles, permissions, or private data.
3. Presence GET cannot be used to infer hidden private group membership beyond IDs the frontend already knows.
4. Presence routes require auth.
5. Presence routes are safe from SQL injection.
6. Presence ID parsing cannot create arbitrary cache keys.
7. Presence data does not persist beyond TTL.
8. Presence works only for authenticated internal users.
