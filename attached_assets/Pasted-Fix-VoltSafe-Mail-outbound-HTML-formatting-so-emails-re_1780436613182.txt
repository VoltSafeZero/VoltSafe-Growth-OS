Fix VoltSafe Mail outbound HTML formatting so emails render consistently across Gmail, Outlook, Apple Mail, Spark, mobile, desktop, and VoltSafe Mail.

Bug:
An email composed in VoltSafe Mail looked correct before sending, but after delivery the received email rendered incorrectly across multiple clients:
- Bold styling expanded far beyond the intended selected text.
- Some paragraphs became bold when they should not be.
- Paragraph spacing was reduced or removed in some clients.
- Formatting rendered inconsistently between Gmail, Spark, Outlook, Apple Mail, mobile, desktop, and VoltSafe Mail.

This is likely caused by malformed or non-email-safe HTML generated by the rich text editor/export pipeline:
- Unclosed or improperly nested <strong>/<b> tags
- Inline formatting leaking across paragraphs
- Markdown-style formatting being converted badly
- Paragraphs/divs not normalized for email clients
- Missing email-safe inline styles
- Over-reliance on browser/editor HTML that mail clients interpret differently

Required fix:
Audit and repair the full outbound email formatting pipeline:

1. Composer rich text editor
- Ensure bold/italic/underline/link/list formatting produces valid HTML.
- Bold must only wrap the exact selected text.
- Bold must never leak into following sentences, lines, paragraphs, bullets, or signature.
- When toggling bold off, the editor must close the bold scope cleanly.
- Prevent nested/overlapping malformed formatting tags.

2. HTML serialization before send
Before sending, normalize/sanitize the composed body HTML:
- Parse the editor HTML.
- Repair invalid nesting.
- Close all formatting tags properly.
- Convert unsupported or risky editor markup into email-safe HTML.
- Remove empty formatting wrappers.
- Prevent <strong>, <b>, <em>, <i>, <u>, <a>, <span> from crossing block boundaries.
- Do not allow inline formatting tags to wrap multiple paragraphs unless the user intentionally selected multiple paragraphs.
- Preserve intentional bold only where selected.

3. Paragraph and line spacing
Normalize email body blocks so spacing is consistent:
- Convert plain text line breaks into safe HTML paragraphs or <br> pairs.
- Preserve blank lines between paragraphs.
- Use email-safe paragraph markup:
  <p style="margin:0 0 16px 0; line-height:1.5;">...</p>
- Avoid relying on CSS classes.
- Avoid unsupported modern CSS.
- Ensure mobile clients do not collapse spacing.
- Ensure Outlook does not strip spacing.

4. Signature formatting
- Signature must not inherit bold/italic/underline from the message body.
- Insert a hard formatting reset before the signature.
- Signature wrapper should use explicit inline styles.
- Signature text should render consistently in all clients.
- Links in the signature should remain clickable and styled safely.

5. Email-client-safe output
The final sent email HTML should be table/simple-block safe and inline-style based:
- No external CSS dependency.
- No Tailwind classes.
- No editor-only classes.
- No unsupported CSS.
- No malformed nested spans.
- No markdown artifacts.
- No accidental global font-weight.
- Include a plain-text fallback generated from the final cleaned HTML.

6. Sending pipeline
Find the exact function that sends outbound email from VoltSafe Mail.
Make sure it sends:
- cleanedHtmlBody
- plainTextFallback

Do not send raw editor state directly.

7. Reply/forward handling
Also fix the same formatting path for:
- new compose
- reply
- reply-all
- forward
- saved draft -> send
- AI-generated email -> Continue in Mail -> send

All routes must use the same HTML normalization/sanitization function.
