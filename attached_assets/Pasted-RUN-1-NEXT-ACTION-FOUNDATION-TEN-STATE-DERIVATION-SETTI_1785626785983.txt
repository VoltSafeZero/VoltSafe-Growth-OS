==================================================
NEXT_ACTIONS TABLE
==================================================

Create next_actions with:

- id SERIAL PRIMARY KEY
- lead_id INTEGER NULL FK → leads.id ON DELETE CASCADE
- account_id INTEGER NULL FK → accounts.id ON DELETE CASCADE
- title TEXT NOT NULL
- description TEXT NULL
- owner_user_id INTEGER NULL FK → users.id ON DELETE SET NULL
- created_by_user_id INTEGER NULL FK → users.id ON DELETE SET NULL
- completed_by_user_id INTEGER NULL FK → users.id ON DELETE SET NULL

- waiting_on TEXT NOT NULL
  CHECK (waiting_on IN ('voltsafe','customer'))

- waiting_since_at TIMESTAMPTZ NOT NULL DEFAULT NOW()

- due_at TIMESTAMPTZ NULL

- blocker TEXT NULL
- snoozed_until TIMESTAMPTZ NULL

- status TEXT NOT NULL DEFAULT 'open'
  CHECK (status IN ('open','completed','cancelled'))

- completed_at TIMESTAMPTZ NULL
- cancelled_at TIMESTAMPTZ NULL

- created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
- updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()

Rules:

- waiting_on has exactly two values:
  - voltsafe
  - customer

- Do not add waiting_on='nobody'.

- No open action means nobody currently owes an action.

- NULL due_at means immediately due.

- For waiting_on='customer':
  - due_at does not drive the nudge timer.
  - waiting_since_at is the authoritative timer.

- For waiting_on='voltsafe':
  - NULL due_at means due now.

- Completed and cancelled rows remain as history and never drive current status.

==================================================
DATABASE TRIGGER
==================================================

Create one database trigger function for next_actions.

ON INSERT:

- set waiting_since_at = NOW() if absent
- set updated_at = NOW()

ON UPDATE:

- always set updated_at = NOW()

- if waiting_on changes:
  - set waiting_since_at = NOW()

- if waiting_on changes to 'voltsafe':
  - set due_at = NULL
  - this means the newly returned VoltSafe action is immediately due
  - do not allow an old customer-wait due date to make it instantly critical

- if status changes to completed:
  - set completed_at = NOW() if absent

- if status changes to cancelled:
  - set cancelled_at = NOW() if absent

- if status changes away from open:
  - preserve waiting_since_at and due_at for history
  - do not delete the row

Unrelated email activity must never update waiting_since_at.

The trigger must be idempotently created through the approved gated migration path.

==================================================
PURE STATUS FUNCTION
==================================================

Create one pure function with explicit inputs.

Return exactly one of TEN states:

- NEVER_CONTACTED
- UNKNOWN
- NO_ACTION
- SCHEDULED
- DUE
- CRITICAL
- WAITING_CUSTOMER
- CUSTOMER_NUDGE_DUE
- BLOCKED
- SNOOZED

Use America/Vancouver calendar dates.

Do not calculate overdue days using:

elapsed milliseconds / 24 hours

Do not calculate calendar days by raw timestamp subtraction.

Normalize relevant timestamps to organization-local calendar dates and compare date ordinals.

America/Vancouver observes DST and must pass both spring-forward and fall-back tests.

Evaluation order:

1. Open action and snoozed_until is still in the future:
   SNOOZED

2. Open action and blocker is non-empty:
   BLOCKED

3. Open action and waiting_on='customer':

   calendar days since waiting_since_at
   greater than customer_wait_nudge_days:
   CUSTOMER_NUDGE_DUE

   otherwise:
   WAITING_CUSTOMER

4. Open action and waiting_on='voltsafe':

   due_at IS NULL:
   DUE

   local due date is after today:
   SCHEDULED

   overdue calendar days <= critical_overdue_days:
   DUE

   overdue calendar days > critical_overdue_days:
   CRITICAL

5. No open action and hasEverContacted === false:
   NEVER_CONTACTED

6. No open action and hasEverContacted === null:
   UNKNOWN

7. Otherwise:
   NO_ACTION

Important:

- expired snoozes must fall through to normal derivation
- completed actions are ignored
- cancelled actions are ignored
- CUSTOMER_NUDGE_DUE is derived only
- never mutate waiting_on automatically
- unknown contact history must never display green No Action Needed
