Proceed with VoltSafe CMS Currents Phase 11A only: Group Direct Messages.

Do not work on Accounts, Contacts, CRM list views, Guest Currents, external collaborators, slash commands, workflow automation, typing indicators, channel search improvements, or unrelated task features.

Goal

Extend Currents Direct Messages from one-to-one conversations to small internal group DMs.

Currents already has:

* current_conversations
* current_conversation_members
* 1:1 DMs
* DM attachments
* Attachment-only DMs
* DM unread/read-state
* DM muting
* Notification preferences
* User picker
* Conversation message feed

Phase 11A should add internal group DMs using the existing conversation/member model.

Scope

Add only:

1. Create group DM with 2+ other internal users
2. Display group DM in Direct Messages list
3. Send/read messages in group DM
4. Group DM unread counts
5. Group DM notifications
6. Group DM mute preference
7. Group DM attachments should work through existing DM attachment path
8. Basic group DM header/member display

Do not add:

* external guests
* channel-like membership management
* adding/removing members after creation unless trivial
* group DM naming/renaming unless simple
* typing indicators
* read receipts per person
* slash commands

Keep Phase 11A focused on creating and using small internal group DMs.

Data model

Reuse existing tables if possible.

Conversations

Use:

* current_conversations.type = 'group_dm'

For group DMs, participant_key should be deterministic if useful:

* sorted user IDs including creator
* prefix: group:1:4:9

Decision needed:

* If exact same participant set starts a group DM again, prefer reopening existing conversation instead of duplicating.
* If that is difficult, allow duplicate group DMs but document it.

Preferred:

* dedupe exact participant set via participant_key.

Members

Use current_conversation_members.

Each member gets:

* conversation_id
* user_id
* last_read_message_id
* is_muted
* created_at

Backend routes

Create/open DM

Update existing:

POST /api/current/dms

Support either:

{
  "userId": 123
}

for 1:1 DMs, or:

{
  "userIds": [123, 456, 789]
}

for group DMs.

Rules:

1. Requires authentication.
2. userId preserves existing 1:1 behavior.
3. userIds creates group DM.
4. Reject empty userIds.
5. Reject self-only group.
6. Remove duplicates.
7. Exclude current user from submitted list, then add current user internally.
8. Require at least 3 total members for group_dm:
    * current user + at least 2 others
9. Validate all users exist and are active/internal.
10. Use deterministic participant key if deduping.
11. Return existing exact group if participant key exists.
12. Otherwise create conversation + all member rows transactionally if possible.
13. Do not break existing 1:1 DMs.

List DMs

Update:

GET /api/current/dms

Return both:

* dm
* group_dm

For each item include:

{
  "id": 123,
  "type": "group_dm",
  "displayName": "Alex, Sarah, Trevor",
  "members": [
    { "id": 1, "name": "Trevor", "email": "..." }
  ],
  "otherUsers": [
    { "id": 4, "name": "Alex", "email": "..." }
  ],
  "lastMessage": {},
  "unreadCount": 2,
  "isMuted": false
}

For 1:1 DMs, preserve existing fields so frontend does not break.

Send message

Update notification creation in:

POST /api/current/dms/:id/messages

Rules:

1. Sender must be member.
2. Notify all other non-muted members.
3. Do not notify sender.
4. Respect is_muted.
5. Attachment-only DMs still work.
6. last_message_at updates.

6. No duplicate notifications.

Verify:

2. User cannot create group DM with external/guest users if such users exist.

6. User cannot mute group DM unless member.

10. Muted members are not notified.
