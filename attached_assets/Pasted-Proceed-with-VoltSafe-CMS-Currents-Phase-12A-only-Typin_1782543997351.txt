Goal

Add lightweight typing indicators to Currents for:

1. Channels
2. 1:1 DMs
3. Group DMs
4. Thread replies if low-risk

Currents now supports channels, DMs, group DMs, attachments, unread/read state, muting, channel management, archived channels, structured items, AI summaries, and task source links. Typing indicators should make conversations feel more alive without introducing a large real-time infrastructure change.

Preferred architecture

Use an in-memory TTL map for Phase 12A.

Example conceptual key:

* channel:${channelSlug}
* dm:${conversationId}
* thread:${rootMessageId}

Each typing event stores:

{
  "userId": 123,
  "name": "Trevor",
  "expiresAt": 1710000000000
}

TTL:

* 5–8 seconds

The client sends a typing ping at most every 2–3 seconds while text is changing.

The client polls typing state every 3–5 seconds while viewing a conversation.

This avoids schema changes.

Backend routes

Add authenticated routes under /api/current.

Send typing signal

POST /api/current/typing

Body:

{
  "scope": "channel",
  "channelSlug": "sales"
}

or:

{
  "scope": "dm",
  "conversationId": 123
}

or, if supporting threads:

{
  "scope": "thread",
  "rootMessageId": 456
}

Rules:

1. Requires authentication.
2. Validate scope.
3. For channel:
    * channel must exist
    * channel must not be archived
4. For DM/group DM:
    * user must be current member
5. For thread:
    * user must be allowed to view/reply to root message
    * if root belongs to archived channel, reject typing
6. Store typing event in TTL map.
7. Return success.

Get typing state

GET /api/current/typing

Query examples:

* /api/current/typing?scope=channel&channelSlug=sales
* /api/current/typing?scope=dm&conversationId=123
* /api/current/typing?scope=thread&rootMessageId=456

Rules:

1. Requires authentication.
2. Same access checks as POST.
3. Return active typers excluding current user.
4. Expire stale entries.
5. Limit returned typers to reasonable number, e.g. 3 names plus count.

Response:

{
  "typers": [
    { "userId": 4, "name": "Alex" }
  ],
  "count": 1
}

Frontend requirements

Composer typing pings

When user types in:

* channel composer
* DM/group DM composer
* thread composer if supported

Send typing signal:

1. Only when draft text is non-empty.
2. Throttle to every 2–3 seconds.
3. Stop naturally when user stops typing; TTL expires.
4. Do not send typing signals in archived channels.
5. Do not send typing signals after message send clears composer.
6. Do not spam the server on every keystroke.

Typing indicator display

Show below message feed or above composer:

Examples:

* Alex is typing…
* Alex and Sarah are typing…
* Alex and 2 others are typing…

For DMs/group DMs:

* Show only other members.
* Do not show current user typing.

For channels:

* Show other internal users typing in that channel.

For threads if implemented:

* Show inside ThreadPanel near reply composer.

UI polish

1. Small, subtle text.
2. Animated dots optional.
3. Does not shift layout aggressively.
4. Dark mode polished.
5. Hidden when no one is typing.
6. Works with polling/refetch without flicker.

Security requirements

Verify:

1. User cannot send typing signal to DM/group DM they are not part of.
2. User cannot read typing state for DM/group DM they are not part of.
3. User cannot type into archived channel.
4. User cannot read/write thread typing where they lack access.
5. Typing state does not leak private conversation membership.
6. Stale entries expire.
7. Server memory cannot grow unbounded:
    * cleanup stale entries
    * cap map size or expire on each read/write
