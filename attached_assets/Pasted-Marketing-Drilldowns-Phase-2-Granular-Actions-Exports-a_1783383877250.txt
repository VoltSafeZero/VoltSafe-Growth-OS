Goal:
Upgrade Marketing drilldowns from “view underlying records” to “inspect, fix, export, and act.”

Every Marketing drilldown should help users answer:
- What records make up this number?
- Why are they in this bucket?
- What needs to be fixed?
- What action can I take next?

Do not modify unrelated modules.
Do not weaken compliance.
Do not fake data.
Do not return unpaginated large lists.
Do not break existing Marketing drilldowns.

2. Add CSV export for Marketing drilldowns

Add export support for drilldown results.

Preferred API:
GET /api/marketing/drilldown/export

Query params should match /api/marketing/drilldown:
- metric
- segment
- status
- campaign_id
- audience_id
- jurisdiction
- consent_status
- date_from
- date_to
- search
- sort

Requirements:
- requireAuth + crm:view
- enforce same permission logic as drilldown endpoint
- export only the filtered dataset
- reasonable max export cap, e.g. 5,000 rows
- include generated_at and filters in metadata if practical
- do not export hidden/private fields
- do not export unsubscribed/suppressed records in a way that encourages accidental sending

UI:
- Add “Export CSV” button inside MarketingDrilldownSheet
- Disable or explain when export is unavailable
- Show safe loading/error state

3. Add drilldown count reconciliation

The drilldown total should match the card count.

When opening a drilldown:
- refresh total from backend
- show total in drawer header
- if card count was passed and differs from backend total, show small note:
  “Updated count: X”
- log mismatch in development only

Do not silently show a different number.

4. Compliance remediation actions

For compliance-related drilldowns, add safe single-record actions.

Examples:

Unknown Jurisdiction:
- open CRM record
- edit country/province/state if existing edit flow supports it
- mark for review

Unknown Consent:
- open CRM record
- update consent status if existing flow supports it
- mark for consent review

Missing Consent Proof:
- open CRM record
- add/update consent source/proof if existing flow supports it
- create follow-up task if task system supports it

Expiring Implied Consent:
- create re-permission follow-up
- add to re-permission audience if existing audience flow supports it

Unsubscribed/Suppressed:
- open CRM record
- view suppression reason
- do not allow unsafe “resubscribe” bulk actions

Campaigns Blocked:
- open campaign
- view blocked recipients
- view reasons
- fix audience/compliance issue where supported

Important:
Do not add risky bulk compliance changes.
Single-record actions only unless existing safe workflow already exists.

6. Improve campaign metric drilldowns

Campaign drilldowns should show granular event context.

For sent/opened/clicked/replied/bounced/unsubscribed/blocked:
- campaign name
- sequence step
- subject
- recipient
- contact/account link
- event type
- event timestamp
- reason if failed/blocked/bounced
- CTA URL if click event exists
- reply sentiment/category if available
- opened/clicked counts if available

Add quick actions:
- open campaign
- open contact
- open account
- open email thread if available
- create follow-up task if available

11. Improve zero-count states

Zero-count drilldowns should be educational.

Examples:
- Express Consent: 0
  “No contacts currently have express consent. Add consent proof from CRM records or create a consent capture workflow.”

- Campaigns Blocked: 0
  “No campaigns are currently blocked by compliance checks.”

- Spam Complaint Rate: 0
  “No spam complaints found for the selected period.”

No dead blank drawers.

- search does not trigger unbounded queries
- export has a separate cap

Add tests/source checks for capped exports and pagination.

13. Permissions

Marketing drilldowns must respect:
- auth
- crm:view
- marketing/campaign permissions if they exist
- contact/account visibility rules if they exist

No user should be able to export or drill into records they cannot normally view.
