Goal:
Evolve Today into a CEO Cockpit that keeps Trevor close to the highest-value signals inside VoltSafe:
- what each team member is working on
- what is blocked
- what has not moved
- what needs CEO attention
- what commitments were made
- what follow-ups are overdue
- what should be covered in upcoming 1:1s
- which people/projects/accounts/deals are creating the most urgency

This should feel like an executive communication radar and team operating system.

Important philosophy:
Build this as a signal-and-accountability tool, not a surveillance tool.
Do not track keystrokes.
Do not track mouse movement.
Do not create invasive productivity scoring.
Do not shame people.
Do not expose private DMs broadly.
Do not infer intent from silence too aggressively.
Surface work signals, blockers, commitments, and communication gaps from existing CMS data.

Primary user:
Trevor / CEO.

Secondary users:
Managers may eventually get a scoped version, but this phase should focus on CEO Cockpit behavior.

3. Team Pulse section

Create a “Team Pulse” section.

For each team member, show:
- name
- role/title if available
- active tasks count
- overdue tasks count
- blocked tasks count
- projects owned
- recent activity count
- last visible work signal timestamp
- upcoming 1:1 if available
- open commitments
- CEO attention flag if needed

Important:
Do not create a simplistic productivity score.
Instead use signal labels:
- Active
- Needs follow-up
- Blocked
- Quiet
- Overloaded
- Waiting on CEO
- No current signals

Each label must be explainable from real data.

Example:
“Quiet — no task/project/message activity in 5 business days.”

4. Blockers section

Surface blockers across the company.

Sources:
- blocked tasks
- blocked projects
- blocked installs/deployments
- procurement blockers
- support blockers
- campaign blockers
- Capital blockers only for Capital users
- CURRENTS messages containing blocker-style signals if safe and practical

Each blocker should show:
- title
- owner
- source module
- age
- severity
- what is blocked
- next action
- link to source record
- optional “Ask for update” action

Do not invent blockers.
Do not rely only on AI text interpretation in this phase.

5. Silence Watch section

Surface areas where there has been no visible movement.

Examples:
- assigned task overdue with no update
- project stale for 7+ days
- open support ticket stale
- deal/opportunity stale
- marketing campaign draft untouched
- procurement item pending too long
- team member with no visible work signal for X days

Important:
This must be framed carefully.

Use language like:
- “Needs check-in”
- “No recent update”
- “Stale item”
- “No visible movement”

Avoid:
- “Not working”
- “Unproductive”
- “Lazy”
- “Bad performer”

Each item must show why it appeared.

6. Commitments section

Track commitments and promises.

Sources:
- tasks created from meetings
- follow-up tasks
- manually assigned tasks
- CURRENTS messages if explicit task/commitment markers exist
- meeting notes action items
- CRM follow-ups

Show:
- commitment title
- owner
- due date
- source
- status
- days overdue if overdue
- link to source
- “nudge owner” action if safe

If commitment extraction does not exist yet:
- only use existing tasks/action items
- document AI commitment extraction as follow-up

7. 1:1 Operating System

Add a 1:1 section for team members.

For each direct report/team member:
- next scheduled 1:1 if available
- last 1:1 if available
- open action items from prior 1:1
- overdue commitments
- blockers
- wins/recent progress
- suggested agenda items

Suggested agenda categories:
- Blockers
- Commitments
- Priorities
- Support needed
- Decisions needed
- Wins

If no 1:1 data exists:

Do not auto-create calendar events unless explicitly requested.

Each item should show:

- source
- age
- owner/requester
- action link

Sources:

Metrics:

Privacy:

10. “Ask for Update” action

Add safe communication actions.

For a blocker/stale commitment/team pulse item, add:
- “Ask for update”

Behavior:
- creates a draft CURRENTS message, not auto-send
or
- opens CURRENTS DM composer prefilled with a suggested message
or
- creates a task/comment requesting update

Do not auto-send messages.

Suggested copy:
“Quick check-in — can you post a brief update on this today? Specifically: current status, blocker, and next step.”

If draft/prefill infrastructure does not exist:
- add copy-to-clipboard suggested message
- document real prefilled CURRENTS DM as follow-up
