Marketing Drilldowns Phase 2 — Granular Actions, Exports, and Drilldown Polish

Current completed state:

Marketing Universal Drilldowns are complete:
- GET /api/marketing/drilldown
- 31 metric types
- requireAuth + crm:view
- reusable MarketingDrilldownSheet
- Compliance Dashboard, Marketing Dashboard, Campaigns, Hot Accounts, Replies, and Audiences are wired
- tests/marketing-drilldown.test.cjs passing

Universal Drilldowns are also now complete for:
- Pipeline
- Insights
- Operations
- Work

Goal:
Upgrade Marketing drilldowns from “view records behind a number” to “inspect, fix, export, and act.”

Every Marketing drilldown should help users answer:
- What records created this number?
- Why are they in this bucket?
- What needs fixing?
- What action can I take next?

Do not modify unrelated modules.
Do not weaken compliance.
Do not fake data.
Do not return unpaginated large lists.
Do not break existing Marketing/Pipeline/Insights/Operations/Work drilldowns.

2. Add CSV export for Marketing drilldowns

Add:

GET /api/marketing/drilldown/export

It should support the same filters as /api/marketing/drilldown:
- metric
- segment
- status
- campaign_id
- audience_id
- jurisdiction
- consent_status
- date_from
- date_to
- search
- sort

Requirements:
- requireAuth + crm:view
- same metric whitelist as the main drilldown endpoint
- unknown metric returns 400
- export only the filtered dataset
- cap exports, preferably max 5,000 rows
- do not export hidden/private/internal-only fields
- do not expose suppression/unsubscribe data in a way that encourages unsafe sending
- include generated_at and filter metadata if practical

UI:
- Add Export CSV button to the Marketing drilldown sheet
- Show loading/error states
- Disable or explain export when unavailable

Show where available:

Do not replace existing CRM detail drawers unless already part of the pattern.

5. Compliance remediation actions

For compliance-related drilldowns, add safe single-record actions.

Unknown Jurisdiction:
- open CRM record
- show missing country/province/state
- mark for review if supported

Unknown Consent:
- open CRM record
- show missing consent status/source
- mark for consent review if supported

Missing Consent Proof:
- open CRM record
- show missing proof/source fields
- create follow-up task if task system supports it

Expiring Implied Consent:
- create re-permission follow-up if supported
- add to re-permission audience only if an existing safe workflow exists

Unsubscribed/Suppressed:
- open CRM record
- show suppression reason
- do not add unsafe resubscribe/bulk actions

Campaigns Blocked:
- open campaign
- show blocked recipients
- show block reason
- link to audience/compliance issue where possible

Important:
Do not add risky bulk compliance changes.
Single-record remediation only unless there is already a safe existing workflow.
