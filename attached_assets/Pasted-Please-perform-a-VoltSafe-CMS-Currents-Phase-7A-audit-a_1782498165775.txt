Please perform a VoltSafe CMS Currents Phase 7A audit and polish pass only.

Do not add Guest Currents, direct messages, slash commands, external collaborators, workflow automation, new task features, or unrelated CRM features.

Goal

Verify that Mark as Decision / Risk / Requirement is stable, useful, polished, and correctly wired across Currents.

This is an audit/polish pass for the Phase 7A feature that was already implemented.

Audit scope

Audit only:

1. current_structured_items table/migration
2. Mark/unmark structured item backend routes
3. Structured item list route
4. Structured badges on messages
5. Mark as dropdown/menu
6. Channel Currents support
7. Channel thread reply support
8. Record Currents support
9. Record thread reply support
10. Deep-links from structured items
11. Existing Currents regressions caused by Phase 7A

Backend/API checks

Verify:

Table / migration

1. current_structured_items is created idempotently.
2. Required columns exist:
    * id
    * message_id
    * item_type
    * created_by
    * created_at
    * updated_at
    * notes
    * severity
    * status
    * object_type
    * object_id
    * channel_id
    * thread_root_id
    * source_meta
3. item_type is constrained to:
    * decision
    * risk
    * requirement
4. Duplicate same-type marks are prevented.
5. Same message can support multiple different structured item types if intended.
6. Indexes are sensible for message lookup, channel lookup, record lookup, and list route performance.

Mark route

Verify:

POST /api/current/messages/:id/structured

1. Requires authentication.
2. Validates message id.
3. Rejects invalid itemType.
4. Rejects deleted messages.
5. Works for channel top-level messages.
6. Works for channel thread replies.
7. Works for record top-level messages.
8. Works for record thread replies.
9. Infers and stores correct source context:
    * channel id / slug if channel message
    * objectType / objectId if record message
    * threadRootId if reply
10. Upsert behavior is safe and does not create duplicates.
11. Returns the structured item payload.

Unmark route

Verify:

DELETE /api/current/messages/:id/structured/:itemType

1. Requires authentication.
2. Validates message id.
3. Validates item type.
4. Removes only the requested type.
5. Does not remove other structured item types on the same message.
6. Is safe if item is already absent.
7. Updates frontend correctly after unmark.

List route

Verify:

GET /api/current/structured

Check filters:

1. scope=channel&channel=general
2. scope=record&objectType=account&objectId=ID
3. itemType=decision
4. itemType=risk
5. itemType=requirement
6. limit

Verify returned payload includes:

* item id
* itemType
* notes
* severity/status if used
* message id
* threadRootId
* message preview
* message author
* createdBy
* createdAt
* channel slug/name or record objectType/objectId
* actionUrl/deep-link back to source message/thread

Deep-link checks

Verify structured item action URLs:

Channel message

Expected:

/current?channel=CHANNEL_SLUG&message=MESSAGE_ID

Channel thread reply

Expected:

/current?channel=CHANNEL_SLUG&thread=THREAD_ROOT_ID&message=MESSAGE_ID

Account record message

Expected:

/accounts/OBJECT_ID?tab=current&message=MESSAGE_ID

Account record thread reply

Expected:

/accounts/OBJECT_ID?tab=current&thread=THREAD_ROOT_ID&message=MESSAGE_ID

Contact record message/thread

Use the actual existing Contact route with:

tab=current&message=MESSAGE_ID

and thread param when applicable.

Opportunity record message/thread

Use the actual existing Opportunity route with:

tab=current&message=MESSAGE_ID

and thread param when applicable.

Lead record message/thread

Expected:

/opportunities?selected=LEAD_ID&tab=current&message=MESSAGE_ID

Thread reply:

/opportunities?selected=LEAD_ID&tab=current&thread=THREAD_ROOT_ID&message=MESSAGE_ID
