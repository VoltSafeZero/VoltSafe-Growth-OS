Specific Commit 7 reminders:
	•	The backfill should be triggered automatically as part of the OAuth completion flow, before the user lands on their inbox. Critical UX moment: a brand-new connection should never show an empty inbox. The user should land on a populated inbox, even if backfill is still completing.
	•	“Visible progress” means the user can see what’s happening. Suggested approach: a progress bar or counter at the top of the inbox or in the account-settings area, updating in real-time. Don’t be shy about it — silence makes users think the product is broken.
	•	The backfill should be abortable. If the user clicks “stop” or navigates away, the backfill should pause cleanly, leaving whatever has already been backfilled in the database. Resume on next OAuth completion or via an admin endpoint (Commit 8 scope).
	•	Reuse existing infrastructure: backfill-service.ts (or whichever canonical backfill module exists per the earlier audit) is already there. Don’t reimplement the backfill itself; just trigger it and add the progress UI.
	•	Rate-limiting: should respect Gmail API quotas. The 5-in-flight cap from Commit 2 applies here too. Don’t blast Gmail’s API on a fresh connection.
	•	Per-account state: backfill progress should be stored on the email_accounts row (or a sibling table) so progress survives page refreshes and multiple users can see the same state if they’re admin viewers.
