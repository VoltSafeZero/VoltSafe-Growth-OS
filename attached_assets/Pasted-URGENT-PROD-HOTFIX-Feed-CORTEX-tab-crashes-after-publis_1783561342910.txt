URGENT PROD HOTFIX — Feed CORTEX tab crashes after publish

Context:
The newly published Feed CORTEX page is crashing in production.

Observed:
Route:
- /feed-cortex

Production UI shows generic error boundary:
- “Something went wrong”
- “An unexpected error occurred. Please reload and try again.”

User/session shown in screenshot:
- Advisor Test

This means the route loads, but the React page crashes during render or initial data handling.

Task:
Find and fix the production crash immediately.

Likely cause:
The Feed CORTEX page was built/tested mostly structurally, but a lower-permission user like Advisor Test is likely receiving a 401/403/non-array/null response from one of the Feed Cortex API calls, and the frontend is treating it like a normal array/object.

This may be the same class of bug as the Tasks crash:
- backend returns `{ message: "..." }`
- frontend assumes array
- `.map()` / `.filter()` / `.length` / property access throws
- error boundary catches it

Required investigation:
1. Reproduce locally as Advisor Test or equivalent restricted user.
2. Open /feed-cortex.
3. Check browser console for exact React error.
4. Check network responses for Feed Cortex endpoints:
   - history
   - cortex status
   - today learned
   - ask cortex
   - any URL intel query
5. Check server logs for 401/403/500.
6. Identify the exact render-time crash.

Fix requirements:
1. Feed CORTEX must not crash for any authenticated user.
2. All API responses must be shape-guarded before render.
3. Any array usage must be protected:
   - Array.isArray(data) ? data : []
4. Any object usage must be protected:
   - data && typeof data === "object" ? data : safeDefault
5. Optional fields must be guarded:
   - title
   - domain
   - canonical_url
   - category
   - importance
   - created_by
   - created_at
   - tags
   - summary
   - learned bullets
6. If an endpoint returns 401/403:
   - show a controlled inline permission/empty state
   - do NOT crash the whole page
7. If an endpoint returns 500:
   - show controlled inline error state
   - do NOT crash the whole page
8. If no history is available:
   - show empty state:
     “Cortex has not learned anything new yet.”
9. If Advisor Test lacks permission to see Cortex history:
   - page should still render the brain/feed UI
   - history panel should show permission-safe message
   - Ask Cortex should show disabled/permission-safe state if needed

Specific areas to audit:
- FeedCortexPage component
- useQuery calls in Feed Cortex
- history/today learned mapping
- Cortex status calculations
- learned-summary bullet generation

- Ask Cortex response rendering

  - `.map(`

  - `.reduce(`
  - `.sort(`
  - `.length`
  - `Object.keys`
  - nested optional field access without `?.`

  - history: []
  - today: []
  - status: { totalUrls: 0, learnedToday: 0, inAiContext: 0, topDomain: null }

- If Advisor Test should be allowed to feed Cortex, confirm POST route allows it.
