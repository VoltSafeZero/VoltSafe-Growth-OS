Backend route checks

GET /api/current/channels/:slug/participants

Verify:

1. Requires authentication.
2. Validates slug safely.
3. Rejects injection attempts.
4. Existing active channel returns clean response.
5. Archived channel returns clean read-only response.
6. Missing channel returns 404.
7. Invalid slug returns 400, not 500.
8. Participant source is correct:
    * message authors
    * channel preference users
9. Does not accidentally include unrelated users.
10. Suspended/deactivated users are excluded.
11. Inactive users are excluded if relevant to current schema.
12. Response includes only:

* channel id/slug/name/description/isArchived
* participant id/name/email

13. Does not expose password, role, permissions, status, private fields, or session data.
14. Results are capped at 100.
15. Results are sorted consistently.
16. Query avoids N+1 behavior.
17. SQL injection is not possible through slug.

Participant definition checks

Verify the product wording is accurate.

Because channels do not yet have formal membership, this panel should not imply formal “members” if the backend is actually returning participants.

Confirm UI copy uses one of:

* People
* Channel participants
* People in this channel

Avoid misleading copy like:

* Members

unless formal channel membership exists.
