Proceed with VoltSafe CMS Currents Phase 10B only: Hide Muted From Currents Unread Badge Preference.

Do not work on Accounts, Contacts, CRM list views, group DMs, Guest Currents, external collaborators, slash commands, workflow automation, typing indicators, channel search improvements, or unrelated task features.

Goal

Add a user-level preference that controls whether muted channels/DMs count toward the main Currents unread badge.

Phase 10A added per-channel and per-DM muting. Muted conversations still show unread counts, visually subdued. Phase 10B should let users decide whether muted unread messages appear in the global Currents nav badge.

Scope

Add only:

1. User preference: include or exclude muted conversations from global Currents unread badge
2. Backend unread-count behavior respects this preference
3. Small UI control to toggle the preference
4. Tests/audit for the above

Do not change per-channel/DM unread badges unless needed. Muted conversations should still show their own subdued unread counts.

Before coding, inspect:

Desired behavior

Add a user-level setting:

hideMutedFromCurrentsBadge

Default: false

Meaning:

* false: main Currents nav badge includes unread from muted channels/DMs.
* true: main Currents nav badge excludes unread from muted channels/DMs.

Important:

* Muted channel/DM row-level unread badges should still show subdued unread counts.
* This setting only affects the global/nav Currents badge total.

Data model

Prefer using an existing user preferences/settings table if one exists.

If no suitable table exists, add a small additive table:

current_user_preferences

Fields:

* user_id
* hide_muted_from_badge
* created_at
* updated_at

Unique:

* user_id

Migration must be idempotent.

Backend routes

Add authenticated routes under /api/current.

Get preferences

GET /api/current/preferences

Return:

{
  "hideMutedFromCurrentsBadge": false
}

Update preferences

PUT /api/current/preferences

Body:

{
  "hideMutedFromCurrentsBadge": true
}

Rules:

1. Requires authentication.
2. Only updates current user’s preferences.
3. Boolean only.
4. Returns updated preferences.
5. Does not expose other users’ settings.

Unread-count behavior

Update:

GET /api/current/unread-counts

Behavior:

1. Load current user preference.
2. If hideMutedFromCurrentsBadge === false, preserve existing behavior.
3. If hideMutedFromCurrentsBadge === true:
    * Exclude unread from muted channels.
    * Exclude unread from muted DMs.
4. Do not change row-level unread counts in /api/current/channels or /api/current/dms.
5. Sender’s own messages still excluded.
6. Deleted messages still excluded.
7. Archived channels still excluded by write-blocking / existing unread logic.

Muted channel exclusion

Muted channel means current user has current_channel_preferences.notification_level = 'muted'.

Muted DM exclusion

Muted DM means current user’s current_conversation_members.is_muted = true.

Frontend requirements

Add a small setting in Currents.

Preferred location:

* Currents sidebar footer/settings area, or
* near the Direct Messages / Channels notification controls, or
* a small Notification settings control in the Currents header.

Keep it simple.

UI copy:

* Label: Hide muted unread from badge
* Helper text: Muted channels and DMs will still show their own unread counts.
* Toggle switch or checkbox.

Behavior:

1. Loads current preference.
2. Toggle updates backend.
3. Shows toast:
    * enabled: Muted unread hidden from Currents badge
    * disabled: Muted unread included in Currents badge
4. Refetches /api/current/unread-counts.
5. Nav badge updates accordingly.
6. Does not affect muted row-level unread badges.
