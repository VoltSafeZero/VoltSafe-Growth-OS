Please perform a VoltSafe CMS Currents Phase 11B Group DM Member Management audit and polish pass only.

Backend checks

POST /api/current/dms/:id/members

Verify:

1. Requires authentication.
2. Current user must be a current member.
3. Conversation must be group_dm.
4. Rejects use on 1:1 DMs.
5. Rejects missing/invalid conversation id.
6. Rejects empty userIds.
7. Rejects non-array userIds.
8. Dedupes duplicate submitted users.
9. Excludes existing members.
10. Rejects if no new users remain.
11. Validates all users exist.
12. Rejects inactive/deleted users.
13. Rejects external/guest users if such users exist.
14. Enforces max group size.
15. Inserts member rows without duplicates.
16. Preserves existing members’ read state.
17. Preserves existing members’ mute state.
18. Returns updated sorted member list.
19. Notifies newly added users only.
20. Does not notify existing members unless intentionally designed.
21. Does not notify the actor unless intentionally designed.
22. Handles race/duplicate insert safely enough.

POST /api/current/dms/:id/leave

Verify:

1. Requires authentication.
2. Current user must be a current member.
3. Conversation must be group_dm.
4. Rejects use on 1:1 DMs.
5. Deletes or deactivates only current user’s membership row.
6. Does not delete the conversation.
7. Does not delete messages.
8. Remaining members keep access.
9. Leaving user immediately loses access.
10. Leaving user no longer sees group in GET /api/current/dms.
11. Leaving user cannot open group via /current?dm=ID.
12. Leaving user cannot send message.
13. Leaving user cannot mark read.
14. Leaving user cannot mute/unmute.
15. Leaving user cannot upload/list/download attachments.
16. If leaving would leave one or zero members, behavior is intentional and documented.

Existing route membership checks

* GET /api/current/dms
* GET /api/current/dms/:id/messages
* POST /api/current/dms/:id/messages
* POST /api/current/dms/:id/read
* PUT /api/current/dms/:id/preference
* POST /api/attachments for current_message
* GET /api/attachments for current_message
* GET /api/attachments/file/:fileName
* /api/current/unread-counts
* notification fan-out
* hide-muted badge logic

No route should still treat a left user as a member.

Verify:

1. Leave button appears only for group DMs.
2. Leave requires confirmation.
3. Cancel confirmation works.
4. Confirm leave calls backend.
5. Success removes conversation from sidebar.
6. Success navigates to safe fallback.

Notification behavior

Verify:

1. Newly added users receive a clear notification if implemented.
2. Notification action URL opens the group DM.

Security checks

Verify:

1. Non-member cannot add members.
2. Non-member cannot leave a group they are not in.
3. Member cannot add inactive/deleted users.
4. Member cannot add external/guest users if such users exist.
5. Member cannot add duplicate existing members.
6. Member cannot exceed group size limit.
7. Left user cannot read/send/mark-read/mute/upload/list/download attachments.
8. Left user cannot access group DM by deep-link.
9. Attachment guards respect current membership after leave.
10. Notifications do not leak group details to non-members.
11. SQL injection is not possible through userIds.
12. Hard-delete membership does not orphan unsafe access.
