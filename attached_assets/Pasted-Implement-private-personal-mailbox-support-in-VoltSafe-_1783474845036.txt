Implement private personal mailbox support in VoltSafe Mail.

Goal:
Team members must be able to connect their own personal email accounts inside VoltSafe Mail for private sending/receiving, while guaranteeing that no other user, manager, admin, shared team inbox, CRM view, AI feature, or global search can see or access that private mailbox unless the mailbox owner explicitly shares access.

This is a security/privacy feature. Treat it as account-level access control, not just UI filtering.

Core requirement:
A private personal mailbox is visible and usable only by the user who connected it.

Examples:
- Trevor connects burgesstrevor76@gmail.com as a private personal mailbox.
- Only Trevor can see, search, open, send, reply, forward, categorize, tag, or summarize emails from burgesstrevor76@gmail.com.
- Other users/admins may see only safe connection metadata if needed:
  - mailbox exists
  - owner name
  - provider
  - connected/disconnected status
  - last sync timestamp
- Other users/admins must NOT see:
  - sender
  - recipient
  - subject
  - snippet
  - body
  - attachments
  - thread list
  - category counts
  - CRM links
  - AI summaries
  - engagement/open tracking details

Add mailbox visibility types:
- private_personal
- team_shared
- company_managed

If the current schema already has account type, mailbox type, shared account, team inbox, or permission fields, reuse and extend the existing model. Do not invent a duplicate architecture.

Database requirements:
1. Add or confirm fields on Gmail/mailbox account table:
   - visibility_type text not null default appropriate value
   - owner_user_id / connected_by_user_id
   - organization_id / tenant_id if available
   - display_name
   - email_address
   - provider
   - connection_status
   - last_sync_at
   - created_at
   - updated_at

2. Add or confirm mailbox access control table for shared/team mailboxes:
   - mailbox_account_id
   - user_id
   - role/access_level: owner, viewer, sender, manager
   - can_read
   - can_send
   - can_manage
   - created_at

3. Private personal mailbox rule:
   - owner_user_id is the only user with read/send/manage access.
   - No implicit admin access to content.
   - No implicit team access.
   - No global CRM access.

4. Migration:
   - Existing personal connected accounts should be classified carefully.
   - Existing team inboxes like sales@voltsafe.com and support@voltsafe.com should be team_shared/company_managed, not private_personal.
   - Existing user-owned accounts like burgesstrevor76@gmail.com should become private_personal.
   - Log/report migration assumptions.

Backend access-control requirements:
Create/reuse one central mailbox authorization resolver, for example:
resolveMailboxAccess(userId, mailboxAccountId, requestedMode)

It must answer:
- canRead
- canSend
- canManage
- isOwner
- visibilityType
- allowedAccountIds

Use this resolver everywhere. Do not scatter one-off checks.

Every Gmail/Mail endpoint must enforce mailbox access server-side:
- list inbox
- list categories
- counts
- search
- open/read thread
- read attachments
- send
- reply
- forward
- drafts
- archive/delete
- labels/tags
- Marine Related
- Priority Highlights
- CRM links
- engagement/open/click tracking
- AI summarize/generate
- Cortex/save-to-context
- exports
- any background sync read surfaces

Critical:
Frontend filtering alone is not acceptable. API must refuse unauthorized access.

All Inboxes behavior:
- “All Inboxes” for a user should include:
  - that user’s private personal mailboxes
  - team/shared mailboxes that user has permission to read
  - company-managed mailboxes that user has permission to read
- It must NOT include private personal mailboxes owned by other users.

Admin behavior:
Admins may manage connection status and mailbox access grants for team_shared/company_managed mailboxes.
Admins may NOT read private_personal mailbox content unless the owner explicitly grants access.
If the existing app assumes admin can access all Gmail accounts, remove that assumption for private_personal mailboxes.

Frontend requirements:
1. Add mailbox connection flow option:
   When connecting a new email account, ask:
   “How should this mailbox be used?”
   Options:
   - Private personal mailbox — only you can see and use it
   - Shared/team mailbox — visible to selected team members
   - Company-managed mailbox — managed by company/admin policy

2. Default for non-@voltsafe.com personal domains:
   - private_personal

3. Default for obvious team addresses:
   - sales@, support@, info@, hello@, billing@, ops@, admin@ should suggest team_shared
   - still require confirmation

4. In sidebar:
   - Private mailboxes should appear under “My Private Mail”
   - Team/shared mailboxes should appear under “Team Inboxes”
   - Company mailboxes can appear under “Work Mail” or current account section

5. Show privacy indicator:
   - For private mailboxes, show a lock icon and label:
     “Private — only you can see this mailbox.”

6. When switching accounts:
   - Clear reading pane immediately.
   - Cancel/refetch active queries with selected mailbox account scope.
   - Never allow stale email from one account to remain visible under another account.

7. Permission denied UX:
   If user tries to access a private mailbox they do not own:
   - show clean 403 message:
     “You do not have access to this private mailbox.”
   - do not leak mailbox content.

Send/reply requirements:
- Sending from private personal mailbox must be allowed only for the owner.
- Sent mail should remain scoped to that private mailbox.
- Other users cannot see private sent mail.
- Shared/team mailbox sending must respect can_send permission.

AI/CRM/Cortex privacy:
Private personal mailbox content must not be used by:
- global company AI summaries
- CEO Cockpit
- CRM account/contact auto-linking visible to others
- shared Cortex/company context
- team reports
- capital/growth intelligence
unless the owner explicitly saves/shares a specific email or note.

If a private email is manually linked to CRM by the owner:
- default it to private link visible only to owner
- require explicit “Share with team” action before other users can see it

Marine Related:
Marine Related tags and sender rules must be scoped by mailbox_account_id and owner_user_id.
A sender tagged in one user’s private mailbox must not affect any other mailbox.

Search:
- Account-scoped search by default.
- All Inboxes search should include only accounts the user can read.
- Global/admin search must exclude private_personal mailboxes not owned by requester.

Background sync:
- Sync may run server-side for connected private mailboxes.
- Synced content remains protected by mailbox authorization resolver.
- Disconnected private mailbox errors should only show to owner/admin metadata view, not other users.

Audit/security logging:
Add audit logs for:
- mailbox connected
- visibility type selected
- access granted/revoked
- unauthorized access attempt
- private mailbox opened by owner
- send/reply from private mailbox
Do not log private subject/body/snippet content.
