Attachment-only behavior

Current behavior says attachment-only DMs are blocked because body text is required.

Audit and confirm:

1. Attachment-only send is safely blocked.
2. User gets understandable behavior/message.
3. Pending files remain staged if send is blocked.
4. This matches channel Currents behavior.
5. No empty DM messages are created accidentally.

Do not add attachment-only messages in this audit unless there is already a bug causing broken behavior. Just document it clearly.

Security checks

This is the most important part.

Verify:

1. User can only upload attachments to a DM message they are allowed to access.
2. User cannot upload a file to another user’s DM by guessing a current_message ID.
3. User cannot view/download attachments from a DM they are not a member of.
4. Attachment list returned in DM messages is only for authorized DM members.
5. Existing /api/attachments route has adequate permission checks for current_message.
6. Existing /api/attachments/file/:fileName download route enforces attachment ACLs.
7. Deleted DM message attachments are hidden/redacted consistently.
8. No file path leakage.
9. No cross-DM attachment leakage.
10. No channel/record attachment permission regression.

If the existing upload route only checks broad crm:edit permission and does not verify DM membership/object ownership, fix that security gap.
