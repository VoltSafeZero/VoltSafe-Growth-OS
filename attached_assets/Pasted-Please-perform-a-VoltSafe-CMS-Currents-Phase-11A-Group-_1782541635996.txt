Backend checks

POST /api/current/dms

Verify:

1. Requires authentication.
2. Existing { userId } 1:1 behavior still works.
3. New { userIds: [] } group behavior works.
4. Self is excluded safely.
5. Duplicate submitted users are deduped.
6. Empty userIds rejected.
7. Single-user userIds behavior is either rejected or routes to 1:1 intentionally.
8. Group requires current user + at least 2 other users.
9. Upper member limit works and is documented.
10. Inactive/deleted users are rejected.
11. External/guest users are rejected if such users exist.
12. Deterministic participant_key uses sorted IDs.
13. Exact same participant set returns existing group DM.
14. Member rows are created for every participant.
15. Conversation type is group_dm.
16. Race/duplicate insert behavior is safe enough.
17. Existing 1:1 participant key behavior is unchanged.

GET /api/current/dms

Verify:

1. Requires authentication.
2. Returns only conversations where current user is a member.
3. Returns both dm and group_dm.
4. Preserves otherUser for 1:1 DMs.
5. Provides members[] for group DMs.
6. Provides displayName for both 1:1 and group DMs.
7. Group display name excludes or includes current user intentionally and consistently.
8. Handles long member lists gracefully.
9. Last message preview works for group DMs.
10. Attachment-only preview works for group DMs.
11. Unread counts work for group DMs.
12. Muted state works for group DMs.
13. Sort newest first still works.
14. No duplicate rows from multi-member JOINs.

POST /api/current/dms/:id/messages

Verify:

1. Sender must be a member.
2. Works for group DMs.
3. Text-only group DM sends.
4. Text + attachment group DM sends.
5. Attachment-only group DM sends.
6. Sender is not notified.
7. Every other unmuted member is notified.
8. Muted members are skipped.
9. Notification title/body are correct.
10. last_message_at updates.
11. No duplicate notifications are created.
